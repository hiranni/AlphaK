# AlphaK 策略实验与自动调优闭环

日期：2026-10-22。状态：实施设计；用户目标是尽快跑出可审计结果并自动迭代，不以初始策略完美或全量数据齐备为前提。本文件补充 [B/S合同](strategy-decision-contract.md)，不表示调优服务已上线。A股、日频、固定人工1–8只、模拟账户、不全市场扫描等边界继续有效。

## 1. 交付目标：可运行、可比较、可迭代

闭环：冻结数据与规则 → 执行基线 → 产生交易/净值/诊断 → 自动生成参数候选 → 时间验证 → 选出候选或维持原版 → 独立模拟观察 → 累积新数据后再评估。

不要求策略一定盈利。无信号、亏损、参数无改善、数据不足、全部候选失败都是合法结果；必须有明确原因和机器可读报告。自动调优是自动实验与选择，不是自动保证收益。

必须分开三种权限：

- 自动试验：可在冻结边界内生成参数、回测、评估、输出候选，无需每次人工确认。
- 自动影子运行：候选绑定独立模拟实例与账本观察，不影响当前运行实例；rule Agent依实例绑定。
- 自动晋升：只有开启明确版本化的晋升政策、通过门槛才允许替换模拟运行版本；默认先保持人工晋升，不把本次设计请求等同于修改正在运行实例或接入真实交易的授权。

首版验收必须完成自动试验和候选输出。自动晋升作为后续可选能力，不得因尚未实现晋升就让调优循环停在人工改参数。

## 2. 先用可用数据跑通，不等待完整多因子

建立能力分层的独立策略版本：

| 层级 | 输入 | 作用 |
| --- | --- | --- |
| T0 技术运行基线 | 可靠的日线OHLCV、日历、费用与证券规则 | 首个可执行闭环，趋势触发、退出、风险预算 |
| T1 盘面情绪挑战者 | T0 + 可回溯市场宽度/活跃度 | 对照情绪是否有增量 |
| T2 多因子挑战者 | T1 + PIT财报、历史估值、完整Q/O模型 | 对照质量和机会准入 |
| T3 文本挑战者 | T2 + 事前文本/事件及模型版本 | 后续可选，不阻断首版 |

缺情绪或财报时运行T0，必须以T0自己的ID、参数和限制发布，不能声称完整多因子有效，也不能运行中静默删掉T2条件。当前历史不足也可运行描述性回测，并开始前向模拟；不足以做可靠样本外时状态为exploratory，不晋升为validated。

T0研究默认：MA短20/长60，新趋势触发买入；连续2个有效收盘跌破短均线退出；止损8%；最多8只，预算与交易规则沿用B/S合同。数据窗口不足的标的不发信号，报告覆盖和等待原因。首次没有可比较前态时只建立状态，不虚构历史交叉。

初始版本参数不是调优结果。既有workbench技术计算可作为参考，但引擎必须提供独立逐日时钟、订单、账本和报告，不能把最新一次技术分析循环展示当作历史回测。

## 3. 一次实验的输入与产物

实验输入：experiment_id、策略模板/版本、池版本、数据manifest、代码/依赖、日历/公司行动、费用与撮合政策、训练/验证时间、搜索空间、预算、随机种子、评价/晋升政策。输入固定后运行不可修改；修订数据产生新实验。

每个trial保存：参数、父实验、状态、输入hash、开始结束时间、失败原因、信号/决策/订单/成交/拒单、每日净值/现金/持仓、成本、回撤、收益、换手、覆盖、有效交易数和时间切分结果。汇总保存所有候选排序与淘汰原因、当前冠军、候选冠军、同预算基线及最优参数周围表现。

运行失败不能写成零收益；无成交可写合法零/现金收益并注明无信号、资金不够、停牌或条件拒绝。指标未定义写null，不以0冒充Sharpe等。部分区间失败则整条trial不参与晋升，保留诊断。

## 4. 自动搜索：先小网格，后续再扩展

V1不训练大模型，不用LLM自由改代码或风险。采用确定性、有限参数网格；跑完后按固定评价政策排序，能复现也便于解释。后续候选较多再考虑随机/贝叶斯优化，不能绕过试验日志和时间切分。

T0首轮搜索空间（工程候选，非最优结论）：

| 可调参数 | 值 |
| --- | --- |
| MA短窗口 | 10 / 20 / 30 |
| MA长窗口 | 60 / 90 / 120 |
| 跌破退出确认 | 1 / 2 个有效收盘 |
| 止损距离 | 6% / 8% / 10% |

共54组，所有组合短窗口小于长窗口。每组运行相同数据、成本、初始资金和风险预算。实际组合数量、切分及成本敏感性子任务全部计入总计算预算。若资源不足按预注册顺序分批，不只运行“看起来会盈利”的组合。

冻结项：单票风险预算0.5%、总仓位80%、单票20%、组合回撤停机15%、模拟制度、费用、股票池和数据截止。止损变动会使按风险计算的仓位变化，报告中说明这个联动；不声称止损改进与仓位效应完全分离。固定仓位对照用于识别该影响。

T1先固定T0冠军，只比较无情绪、宽度准入、宽度准入+过热限制等少数预注册变体；随后可独立做联合搜索实验，全部计入新试验族，不把局部调参称全局最优。T2同理。禁止一次优化数十项权重和风险限制。

## 5. 时间切分：让调优能持续而不泄漏

首选有足够历史时滚动训练24个月、验证6个月，内部多个过去窗口选参；仅过去训练，去除跨界收益标签和执行持有重叠。这个长度是起点不是充分性证明。没有足够历史时降为较短探索实验，保留标记并不声称正式样本外。

自动搜索使用训练/验证区间，最终未见测试集不进入优化目标。搜索结束冻结一个候选后才评估未见区间；不因测试差再拿同一测试集反复挑参数。测试不通过仍输出失败报告，并让当前版本继续运行。

已经观察过的历史不能“重新切一下”变成新未见测试。持续迭代可以把它纳入开发历史，但下一次正式确认依赖新增未见行情或前向模拟。系统允许自动调优连续运行，同时如实标记证据等级，而不是无限使用同一段历史制造样本外成绩。

所有试验均绑定选择流程版本；跨实验比较也登记累积试验次数。不只记录最终54组而隐去此前人工探索。

## 6. 优化目标：先过滤，再比较，允许没有赢家

第一层有效性过滤：无未来数据、数据覆盖达到实验政策、完整结束、账本守恒、无非法订单、指标可计算。第二层风险过滤：成本后最大回撤、仓位、成本敏感性等符合实验约束。第三层才比较表现。

首版用明确的词典序排序，避免随意加权成难解释总分：

1. 通过有效性与风险约束；
2. 跨验证窗口的净超额日收益均值的中位数更高（同一预注册基准与区间）；
3. 最差验证窗口最大回撤较小；
4. 年化换手较低；
5. 并列时参数离当前版本更近，最后按固定trial_id排序。

每个窗口同时报告绝对净收益、现金和指数/池内基准，不能只凭超额在下跌中为正就隐藏亏损。该排序是工程政策，不是统计显著证明；短历史下可排序探索候选，但不能自动宣称有效。

当前版本也按完全相同区间和成本运行。最优候选未超过当前版或现金基线时，结果为no_improvement，保持当前版本，不为完成调优而强制换参数。没有现有冠军时保留T0固定默认作为对照，不把“网格第一名”自动当可部署冠军。

## 7. 候选确认与过拟合控制

候选需满足完整PIT和执行能力、未见样本外、交易数/有效天数政策、成本加倍、参数邻域及分窗口表现检查。最小样本门槛由政策固定，不把“达到某交易次数”解释为统计充分。建议初始最低门槛为3个验证窗口、合计30笔已闭合交易，并同时披露集中性；达不到则insufficient_evidence而非修改门槛。

在共同日期上比较候选与当前版的净日收益差，按日期区块bootstrap报告区间、回撤差和换手差；择优后的区间可能仍乐观，不能替代未见样本。参数邻域看多数邻近配置是否方向一致；结果只在孤立尖峰更好时标unstable。区间跨零、提升不足或成本上升后消失，可以仅进入shadow而不晋升。

DSR/Reality Check等未实现前不展示伪数值；先做有限搜索、试验登记、时间隔离、基线比较和前向跟踪。持有期、费用、股票池、风险预算也算研究自由度，不只是均线参数。

## 8. 前向运行与晋升规则

选出的challenger拥有独立策略版本、实例和模拟子账本，与champion并行接收未来同一批可用数据；不回写老版本净值，不能用新参数重算历史并拼接成真实连续业绩。研究回算和真实前向曲线分开展示。

默认候选自动进入影子观察，建议初始观察至少60个交易日及10笔闭合交易，未达到就继续积累；仍不代表足够显著。若未来用户开启auto_promote，政策至少要求无数据/执行异常、全部确认门槛通过、风险不恶化、记录晋升原因。没过就维持champion。

晋升不热改running实例。先暂停旧实例并取消可撤未成交订单，核对持仓/资金；下一交易日生效的新实例/版本按明确的交接流程承接或独立分配。已有持仓不能无审计搬账本。V1不做自动持仓迁移，可仅在旧实例空仓并结算、资金解冻后晋升；不满足就等待，不偷偷平仓。Agent版本仍绑定实例且不可运行中切换。

回滚采用以前的不可变版本创建后续运行，不删除不利交易或重写历史。紧急风险暂停优先于优化/晋升；调优器不能自动恢复停机策略，也不能为了降低拒单率松风险。

## 9. 调度、资源和失败恢复

实施后建议手动首次启动，日线更新完成后可增量评估，默认每月进行一次有限调参；月度是运行政策候选，不是当前已设置的自动任务。无新数据或新覆盖不重复全量搜索。数据更新先完成质量检查再冻结新manifest。

本地SQLite单用户首版单个实验工作线程，读快照、分批提交结果，避免长期锁住行情/页面；trial_id由输入与参数内容确定，重复提交幂等。实现运行锁、心跳、取消、预算上限和失败重试；中断后从已完成trial恢复，不把半截结果当完整。

状态：experiment queued/running/completed/cancelled/failed；trial pending/running/succeeded/failed/skipped；selection improved/no_improvement/insufficient_evidence/invalid_data。上述是新概念字段，后续新增schema，不与已有策略/实例status混用。

单轮默认54参数trial，敏感性子任务另列预算；超时或取消保存已完成结果但不发布完整赢家。永久无效数据不无限重试。日志里写明等待什么，不把“没有交易”当计算卡死。

## 10. 实施包与可验收任务

首个实施change应交付：

1. 一个可导入固定池与日线快照的实验入口，明确参考数据/公司行动/费用缺口和结果降级。
2. 可运行的T0策略、日频撮合、现金/持仓/交易费用账本及基线；无需等Q/O或文本。
3. 54组有限搜索、时间切分、共同基线、完整trial结果与固定排序政策。
4. 查询实验状态/结果、导出交易与净值及参数表的接口；UI先表格展示真实数据，不再仅放说明卡片。
5. 无改善与样本不足可正常结束、任务重启恢复、版本隔离、回放只读和缓存不伤账本。
6. 有新数据后能够再次运行并产出新的候选，之后接入独立shadow；自动晋升另开能力且默认关闭。

验收：同一快照同一参数结果一致；费用变化能改变净结果；所有trial可追溯；无交易有原因；未来数据注入被拒；未见测试不被优化器读取；多次搜索不会覆盖旧业绩；champion无改善时不变化。用人工构造行情校验执行，再用真实固定池跑出首份报告。首份亏损或no_improvement也算闭环成功，不算策略有效。

## 11. 设计优先级修订

此前“数据全部完整后再建完整多因子策略”的顺序，调整为“按能力版本先跑T0，边运行边积累，逐级加入情绪和基本面挑战者”。不再等待完美模型，但也不把缺失条件悄悄绕过。下一步工程应围绕实验运行器、账本和调优器展开，而不是继续扩充静态研究页面。
