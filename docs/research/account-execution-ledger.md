# 账户执行账本与当前准入状态

更新：2026-10-26。实现：`apps/api/src/execution.rs`。

## 当前可以做什么

账户 B/S 页包含执行检查、成交记录、当前持仓、资金流水。POST `/api/v1/trading/paper-strategies/{id}/execution` 接受唯一 `request_key`，读取该账户当前配置和最近研究报告，冻结检查上下文并逐股记录阻断原因；同账户同请求键重试返回原 run，不重复记录。GET 同路径读取最近200条检查/成交、最近50次运行、持仓、资金流水及最近500个检查时估值记录。不存在公共原始委托提交接口。

**当前生产路径仅进行准入检查，不调用成交函数，不启用自动交易。** 成交及持仓表结构、整数费用计算和事务记账内核已经建立并通过固定输入测试，但不能把它称为已投入运行的自动成交引擎。`execution_ready` 当前明确为 false。

## 为什么不能直接把研究信号变成交易

1. `trading_calendar` 同时存在 seed 与同步日期，没有逐行官方来源凭证；工作日不等于交易日。
2. 普通 `quote_snapshot` 没有完整、可信的停牌状态、当日上下限价、除权核验及可成交盘口数量；provider_time 缺失时不能以 fetched_at 代替报价发生时间。
3. `buy_candidate` 是历史估计与门槛组合，不是已审核的完整执行策略。`reduce_review` 不能直接当卖单，cooling 的零买入预算也不能当清仓。
4. 现有研究没有独立最终样本外验收、可执行入场时点和完整退出规则；不能声称“回测通过”。

缺项时全部 fail closed。每只股票保存原因，成交记录保持为空。检查的0数量与空成交价不是成交，前端不能绘制为 B/S 成交点。

## 上下文与数据流

账户ID → 不可变 research_workspace 配置 → 对应 research_analysis ID → 运行规则版本 → 账户内最多8只股票的报价观察、日历观察与缺失能力 → 执行检查记录 → 检查时资金与估值状态。

输入在 execution_run.context 中冻结。研究快照引用长期保留，换配置后检查只能读取新workspace的报告。初始入金不复制、不修改。Agent响应、schema校验及Agent绑定尚未接入；本模块不假装是Agent运行时，后续接入必须遵守 `docs/specs/` 的两阶段校验。

## 已实现并以固定输入测试的记账内核

所有现金与成交价格以人民币分存储。买入100股整数手；卖出仅前一自然日期之前的已成交持仓，且只能在已核验的交易日交易，因此构成T+1可用约束；非整数手只能一次卖完。FIFO批次更新，禁止卖空；单股不超过估值权益20%，总仓不超过80%。估值或日历无法验证时不得调用内核。

成交必须有10秒以内、非未来报价，正价、明确可交易状态、当日上下限、公司行动核验和可成交数量。按可成交量上限整笔成交或拒绝，不虚构盘口队列或分笔成交。所有字段由后续可信服务端适配器提供，不允许客户端输入“验证通过”。

费用版本 `cn-mainboard-cost-1`：佣金3bps、每笔最低500分；双向过户费0.1bps；卖出印花税5bps。各项按分向上取整。不利滑点5bps，价格按分向不利方向进位，滑点后越过价格上下限即拒绝。后续变更必须新版本，不覆盖旧流水。这是测试与设计口径，生产启用前还需明确审批配置及适用日期。

同一订单只能一条 execution_fill，成交、现金增减、FIFO批次及订单状态由平台在同一事务写入；任一失败必须回滚整个事务。入金单独存 paper_cash_ledger；现金 = 初始入金 + SUM(execution_cash.amount_fen)。成交/流水不自动清理。当前没有报价估值的持仓，market_fen/equity_fen为null，不以0伪装；空仓时可确定市值0和总资产=现金。
