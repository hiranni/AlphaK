# AlphaK 多因子与情绪策略：B/S 与目标仓位合同

版本：研究草案 0.1，2026-10-22。状态：补齐策略设计，尚未实现或通过实证，不是现有执行服务。适用A股日频、人工固定1–8只、多头和现金、模拟资金与模拟成交。理论与验证方案沿用 [基准模型](quant-baseline-model.md)。本文给出一套可被否证的候选参数，不声称阈值最优。

## 1. 决策对象与基本原则

研究分数是状态，策略触发是事件，订单是执行意图，成交和持仓以模拟账本为准。输出动作：buy（从零建仓或增持）、hold、reduce、sell（目标归零）；不做空。用户展示可细分首次买入/加仓，但不增加与现有action枚举冲突的add动作。

每个判断固定strategy_version、model_version、universe_version、decision_at、input_manifest、账户/实例、Agent版本（绑定仅在实例）、持仓与在途订单版本。任何结果说明依据和失效条件，风险预算以本实例净资产为分母，不使用整个账户资金或其他策略现金。

本文有意不规定“分数越高仓位越大”。先固定风险预算验证情绪择时增量，之后才验证情绪调仓；基本面、情绪和价格条件不能相互抵消。

## 2. 冻结一套候选参数

以下全部属于预注册候选，不是文献最优值。参数变化产生新策略版本。Q/O必须来自已冻结且覆盖完整的模型；组内因子配置未完成时，本策略保持research_incomplete，不自动改用旧技术分。

| 项目 | 候选值/定义 |
| --- | --- |
| 质量准入 | Q≥60；已持有Q<50连续两次不同财报/质量事件更新，产生质量退出；不得把同份财报连续两日当两次证据 |
| 机会准入/维持 | O≥65才允许建立候选；持有期间O<45连续3个有效收盘产生机会退出；不每日按分数调仓 |
| 趋势触发 | C_t>MA20_t>MA60_t，且本日趋势条件true、前一有效交易日false；历史前态未知不算新触发 |
| 价格退出 | C_t<MA20_t连续2个有效收盘；正常价格样本未知中断连续计数，不补成false |
| 市场情绪准入 | 同口径B_t≥0，且过去3个有效交易日B均值≥0；窗口不完整为unknown |
| 过热限制 | 个股C拥挤代理高于过去252日、至少126个有效值的90%分位时，禁止新建及加仓；阈值窗口不含当前 |
| 情绪减仓 | B_t<−0.20连续2个有效收盘；或过热条件连续2日成立，只对当前持仓减半一次 |
| 恢复条件 | B的3日均值≥0且过热false连续3日，解除情绪减仓锁；不立即加仓，仍需加仓门槛 |
| 基础单票预算 | 0.95/N，N为固定池数量，未参与的份额留现金，不向其他股票重分配 |
| 单票上限/现金底线 | 20% / 5% |
| 新建及主动加仓的单票风险预算 | 净资产0.5% |
| 参考止损距离 | 8%，由实际成交建仓成本建立；不随价格下跌放宽 |
| 总仓位上限 | 80% |
| 计划组合止损风险上限 | 净资产3%；仅是计划风险，不是损失保证 |
| 组合回撤停机 | 峰值净值回撤≥15%暂停，禁止自动恢复 |
| 日成交额/单笔上限 | 不超过判断时净资产30% / 50,000元；卖出同样计入 |
| 默认执行 | 收盘后判断，下一交易日开盘尝试；参与率不超过此前20日平均日成交量的1%，不使用当天最终量 |
| 最小调仓阈值 | 与当前持仓差不足1个合法买入单位时不主动加仓；风险卖出按合法卖出规则处理 |

B为全市场宽度代理，C为个股涨幅×成交拥挤代理，其定义见基准模型。当前没有历史宽度、没有足够拥挤参考窗口或Q/O不完整时，本版无法启动自动模拟。允许另建纯技术B1对照版本，不允许运行中静默降级。文本情绪与主观研究V0.1仅展示，不改变数量；经过新实验后才能加入规则。

这些参数可能使策略过于保守或长期持币，这是可观察结果，不因信号少临时放宽。质量高低阈值采用回差，防止一个边界附近反复交易；质量退出不适用于数据缺失，缺失按第6节处理。

## 3. B：从研究状态到首次买入

定义Eligible = Q≥60 AND O≥65 AND 情绪准入 AND 非过热 AND critical_risk=pass AND 数据有效。

首次买入必须同时满足：

1. 无现有持仓、无未终结买单、无冷却/停机锁。
2. 趋势条件false→true后形成最多5个交易日有效的候选窗口；前态未知则不创建候选。
3. 候选窗口内当前Eligible=true且趋势仍为true；情绪稍后确认也可触发，但不得无限追踪旧信号。
4. 计算出的合法目标数量大于零，并通过资金及平台校验。

首次买入后消耗候选，窗口过期、趋势false或关键研究假设失效则撤销。退出后至少冷却3个交易日且需新的趋势false→true，不因仍保持高分第二天买回。同一实例/标的/规则/判断日有幂等键，重跑不重复下单。

## 4. 持有、加仓、减仓与退出

| 状态/动作 | 条件 | 目标 |
| --- | --- | --- |
| hold | 持仓有效、无更高优先条件、无加仓事件 | 股数不变；不因价格上涨超过20%自动当日盘中调整，收盘再检查集中度 |
| buy/add | 距上次买入/加仓至少5个交易日，当前Eligible、趋势仍true、无情绪减仓锁、无未成交冲突订单 | 仅补到预算允许的目标，不超过最近一次买入的已实现单位成本，不摊低成本 |
| reduce | 情绪减仓首次触发 | 以触发时持仓数量的一半为目标，合法卖出取整；锁存该目标直到完成，不能每日继续对半砍 |
| reduce | 收盘超单股/组合上限或风险预算上限 | 目标降至对应上限；不允许趁风险减仓同时买入其他股票 |
| sell | 价格退出、机会退出、质量退出、可靠证据确认核心假设失效 | 目标0，保留待成交退出意图 |
| sell + pause | 止损或强制风险退出 | 个股退出；是否暂停实例由风险类型决定。组合回撤停机时对全部持仓生成风险退出意图 |

不允许加仓摊低：仅当判断价不低于最近实际买入单位成本（含买入费用）才允许add，执行时仍检查。加仓后更新费用加权成本，但不得降低原止损参考价；新止损取max(原止损、更新成本×0.92)。加仓风险距离按该止损重新计算。卖出不重置成本参考，以免减仓人为放松止损。实际实现须处理公司行动后的等价成本/止损同步调整。

止损为收盘价≤止损参考价时生成次日退出意图，不是盘中止损保证；日频模式无法承诺触及即成交。跳空、跌停和停牌可能让损失显著超过8%或预算。初次建仓止损按实际成交成本建立，不用信号日的复权价当成交成本。

## 5. 冲突裁决：一日一标的只保留一个最终目标

优先级从高到低：

1. 平台kill switch/组合回撤停机/合法强制限制。
2. 止损、核心假设失效、正常完整退出。
3. 集中度/组合风险减仓和情绪减仓。
4. 合格加仓或新建。
5. 持有。

多个退出条件合并为目标0并保存全部原因；多个减仓条件取最小目标股数；同日买卖冲突只保留更低仓位。平台kill switch禁止新交易时，自动退出也不能绕过该开关：保留退出意图，按平台允许的风险处置权限执行或等待人工；暂停不代表账本已清仓。

旧买单在退出发生时先撤销/失效，订单状态确认后重新计算净调整量。以已成交股数+仍有效在途净数量计算差额，防止重复；无法确认订单状态时禁止新增买单。卖出优先并不允许用尚未确认的卖出回款提前买入。

## 6. 数据缺失、失效与风险状态

无持仓：任何关键数据unknown/过期，禁止B，记录缺失原因；候选窗口按实际交易日自然到期。

有持仓：数据unknown不等于条件false，不自动触发技术/质量卖出，不新建或加仓。当前可靠价格仍可触发独立止损；无法可靠估值时保持最后可信账面值并标记净值不确定，不能称可靠收益。关键运行数据连续2个交易日不可用时暂停新风险操作并要求人工复核，已有退出意图不删除。

risk=warn由预注册规则决定限制（本版未知的warn默认阻止新买）；risk=block禁止新买并按该风险代码决定是否退出。停牌是执行不可用，不是自动宣告公司价值归零。风险退出必须有可信证据，不能让unknown自动化为卖出。

## 7. 仓位计算：风险预算先于分数

A_t为实例净资产，N为池数量，p为候选执行参考价，s为止损参考价（与p同为原始价格口径）。首次新建计划d=0.08；加仓d=(p−s)/p，p≤s时禁止买入并转退出处理。

    w_base = 0.95/N
    w_risk = 0.005/d
    w_i_raw = min(w_base, 0.20, w_risk, w_liquidity)

流动性最多可买股数先由过去20日平均成交量×1%算出，再转换为对应权重；绝不使用当前日收盘后才知道的最终成交量来决定开盘参与上限。预算还受总仓位80%、计划组合风险3%、现金5%、日换手30%、单笔5万元限制。

总计划风险近似为Σ_i max(p_i−s_i,0)×q_i/A。低于止损的持仓仍必须退出，风险公式不能因max为0就认为安全；退出未完成时其买入预算占用不释放。相关性、跳空、流动性与成本未被该公式完整覆盖，所以它不是组合最大损失估计。

本版同时发生多个候选时不按高分抢资金，采用确定性的同比例缩放：保留既有持仓后，对新增目标增量统一乘α∈[0,1]，使现金、总仓位、组合风险和日成交额都满足；不满足买入单位的部分留现金，不二次给排序靠前者。相同输入给出相同结果，证券代码仅用于确定性处理顺序。已需减仓的组合本日不再新增。

最终买入股数取不超过目标的最大合法数量，并使：

    q×p + commission(q,p) + other_buy_fees(q,p) ≤ 可用买入资金

现金需扣除所有有效订单冻结资金与预留费用；各证券生效日期的交易单位由规则表给出，不能一律硬编码100股。常见100股单位示例q=100×floor(V/(100p))仅作说明，费用不足还需向下调整。退出卖出可卖数量受T+1和零股规则限制，剩余目标等待执行，不伪造成交。

执行前只用开盘已知价/可用价重新验算数量和风险，可下调或取消，不扩大收盘时批准预算；价格大幅向不利方向变化、跌至止损以下、超费用/价差或不可成交时拒单。不得用未来开盘价格提前计算前一晚特征。加仓实际成交导致止损/预算超限时先尝试执行前减量，成交后仍超限则留痕并按风险减仓，不篡改原决策。

卖出减仓按最小必要量向上取可执行卖出单位，避免取整后仍超硬上限；全退出适用合法零股卖出规则；实际无法满足时记录残余风险，不反过来提升限制。

## 8. 数量示例：构造算术，不是实际股票建议

实例净资产10万元，N=8，首次参考价20元，d=8%：

    基础预算=11,875元
    单股20%上限=20,000元
    风险预算对应金额=100,000×0.005/0.08=6,250元

因此在其他限制前最多6,250元。按100股单位、每笔买入费用仅示例取5元：300股需6,005元，计划止损风险480元；400股超预算，不买。未使用部分留现金。即使评分从70升到90，也不自动提高本版风险预算。

同一条件若8只均候选，每只计划风险约0.5%，合计4%，超3%组合计划风险；须先同比例缩小目标，再向下按单位取整。最终可能低于3%，不能为“用满风险”反复优化分配。

情绪减半示例：已持有500股，目标250股；若规则允许的部分卖出单位100股，为不高于减半目标，卖出300股、余200股；若相应证券合法规则不同则使用其规则。不能第二天又把200股减半，除非退出或更高优先风险要求。

## 9. 决策解释与审计字段

每个决策保存：数据截止、模型/策略/池版本、输入哈希、Q/O原值与覆盖、B/C及窗口、趋势前后真值、候选创建/到期、持仓/订单版本、触发原因列表、最终优先级、原目标及约束后目标、损失预算与止损参考、数量取整和费用、缺失/拒绝原因、冷却与锁状态。Agent响应先schema校验再业务校验；平台拥有可信运行时字段，Agent不直接改账本。

buy/sell是意图，不能在下单时把持仓或收益改为已成交。事件状态、订单状态和策略实例状态分别存储；信号失效不能自动删除未结算订单。缓存按季度且可过期，订单、资金、持仓和净值不得随解释缓存清理；回放不下单。

## 10. 与现有契约的差距：实施前必须补齐

现有strategy.schema.json只允许equal_weight/fixed_fraction/volatility_target，缺少本文风险预算方法、Q/O引用、情绪字段、候选窗口与状态机。表达式字段白名单也不含这些研究变量。因此本文不得直接导入为可执行现有策略，禁止借metadata绕过验证。

后续独立OpenSpec变更需：新增决策/仓位政策兼容版本及schema、明确rules.weight语义、数据特征引用、校验状态机、仓位与订单数量、风险处置权限及业务验证。旧示例中的buy weight=0.125、sell weight=1、reduce weight=0.5不得直接复用而不说明分母；本文以绝对目标股数/权重为执行真相，减半仅在首次触发时转换为锁存目标。相同版本应对应唯一规则解析器。

策略定义始终不声明Agent；实例绑定已有rule/llm/hybrid Agent版本。首版建议rule类型执行确定性规则，LLM只做解释，不可临时改阈值、资金或风险限制。

## 11. 验证矩阵与否证标准

先对同一池/时段/成本比较B1固定趋势基线与本合同，随后一次只移除/加入一个模块：质量准入、机会门槛、情绪择时、风险仓位。不能同时更改规则和资金后把差额全部归因情绪。缺Q/O版本无法运行时明确未完成，不用完整样本选择性回避缺失。

必须覆盖以下场景：买卖同日冲突归零；每日重算不重复减半/买单；候选过期不追买；无数据不反向卖出；只有1只候选不分到全部现金；多候选统一缩放；小额资金不够一手不下单；费用使取整后超限再减量；T+1可卖不足保留退出；停牌跌停不能伪造成交；开盘越过止损不买；组合暂停但未平仓正确展示；重启恢复锁存目标；公司行动成本与止损一致调整；退市和数据中断不悄悄删样本。

与简单基线相比，若净效果不稳定、成本/参数变化后消失，或依赖不完整PIT资料，则不发布本策略为有效模型。允许得到“不优于基线”的结果。合约数学检查只保证例子与约束一致，不等于回测验证。

## 12. 实施优先级补充

按用户要求优先跑出数据和自动迭代。完整多因子条件尚不具备时，先以独立T0版本运行技术基线，不等待本合同全部输入；参数搜索、验证和候选运行见 [自动调优闭环](strategy-auto-tuning.md)。本合同是T2挑战者政策，禁止静默降级成T0。
