## 0. 摘要

- 建设一个 **本地优先、可自托管、数据源可插拔的 Web 股票研究工作台**，覆盖「看行情 → 做研究 → 圈定股票池 → 验策略 → 模拟盘 → 盯持仓」的完整链路。
- **产品形态为纯 Web 应用**：浏览器直接访问，不做 Electron/Tauri 等桌面客户端，也不依赖本地安装包。
- **不做全市场扫描**：平台不提供全市场条件选股、全市场排名或批量扫描；每个策略只在用户圈定的股票池内分析，**单策略最多 8 只股票**。
- 首版（MVP）聚焦 **A 股行情、指数/板块详情、个股详情、自选股、K 线与常用技术指标、基本面与公司资料、参考数据、数据管理**，固定为本地单用户，目标是做成一个「每天真的会用」的工具。
- 第二阶段在回测之外增加 **虚拟盘**：**一个虚拟账户下可挂多个策略**，每个策略使用独立子账本、**最多操作 8 只股票**；策略可由 **不同 Agent** 以 `advisory` / `auto` / `shadow` 模式执行，Agent 只输出结构化决策，平台负责校验、风控与虚拟下单。
- **Agent 可读契约**：策略、Agent 与决策均使用 JSON Schema 定义，`docs/specs/` 提供模板、示例与不变量；文档采用稳定 ID、规范用语和可验收条款，Agent 不依赖口头约定。
- **策略可解释与可回放**：每个策略必须声明可量化特征；每次决策记录上下文、信号、规则/Agent 轨迹与校验；回放数据按周/月/季/年缓存，默认季度，超期可清理，且不删除收益/交易数据。
- 股票池管理、策略回测、虚拟盘与多策略运行、预警、组合跟踪放在第二阶段；AI 研究助手、多用户与移动端放在第三阶段。
- 明确不做：实盘交易、投顾荐股、资金托管、高频交易、桌面客户端、全市场扫描、Agent 直接访问互联网或券商接口。
- 关键约束：优先使用免费/开源数据源，所有数据源通过适配器隔离，可替换；所有分析结果与模拟交易必须 **可追溯、可复现**。

### 产品命名更新（2026-10-22）

- 主导航新增「量化」与「实盘」：量化承载策略定义与验证，实盘承载模拟账户及策略实例运行。
- 用户可见模块名称统一使用「实盘」，资金及成交持续标注「模拟资金 · 模拟成交」。本文原有「虚拟盘」为技术语义，指同一模拟交易模块。
- 此命名更新替代 FR-13 中禁止出现「实盘」一词的旧 UI 验收要求；无券商接入、无真实下单、独立模拟账本等约束继续有效。

### 0.2 文档规范：面向 AI Agent

平台采用「人读需求 + 机读契约」双层文档。Agent 必须只依赖仓库文件完成策略配置、决策与校验，不依赖口头约定。

| 规范 | 要求 |
| --- | --- |
| 稳定 ID | 需求、约束、不变量使用 `FR-*`、`NFR-*`、`C*`、`INV-*`，发布后不得复用 |
| 规范用语 | 必须 / 禁止 / 应该 / 不应该 / 可以，对应 RFC 2119 |
| 机读字段 | 策略、实例、Agent、决策、回放缓存使用 JSON Schema 2020-12，`additionalProperties: false` |
| 示例可执行 | `docs/specs/examples/` 下示例必须通过对应 Schema 校验 |
| 单位与时间 | 百分比用小数，bps 用基点，金额 CNY，时间 ISO 8601，A 股时区 `Asia/Shanghai` |
| 版本不可变 | 已发布的策略/Agent 版本不可修改，只能新建版本 |
| 失败关闭 | 校验失败、超时、输出不合法时不得下单，必须记录原因 |
| 可追溯 | 每笔虚拟订单必须关联决策 ID、策略版本、Agent 版本、数据快照哈希 |
| 阅读顺序 | `AGENTS.md` → 本文档 → `docs/specs/README.md` → Schema → 示例 |

| `docs/specs/strategy-analysis-template.md` | 策略分析文档模板 |

## 1. 项目概述

### 1.1 背景与问题

个人投资者的研究流程通常被切散在多个工具里：行情软件看盘、财经网站查财报、Excel 记自选和持仓、脚本跑回测。由此带来几个典型问题：

1. **数据分散**：行情、财务、板块、公告不在一个地方，交叉验证成本高。
2. **工作流不可定制**：现成终端要么太重、要么太贵，股票池和看板无法按自己的逻辑组织。
3. **分析不可复现**：Excel 手工计算容易出错，历史结果缺少数据版本与参数记录。
4. **策略验证门槛高**：从想法到回测需要自己搭数据管道，容易踩未来函数、幸存者偏差的坑。

AlphaK 的切入点不是再做一个「行情网站」，而是把 **数据、研究、验证、跟踪** 收敛到一个可自己掌控的工作台里。

### 1.2 产品定位

> **一句话定位**：本地优先、数据可插拔、结果可复现的 **Web 股票研究工作台**。

产品边界：

- **是**：行情浏览、指数/板块与公司资料、基本面研究、技术分析、股票池（≤8 只/策略）、回测、**虚拟盘与多策略运行**、**Agent 策略执行（advisory/auto/shadow）**、**策略可解释性与只读回放**、预警、组合跟踪。
- **不是**：实盘交易通道、投顾服务、社交跟单、资金托管、桌面客户端、资讯门户、全市场扫描/条件选股、Agent 直接访问互联网/执行任意代码/调用券商接口、伪造回放或用可解释缓存替代绩效数据。

### 1.3 建设目标与成功指标

| 维度 | 目标 | 可量化指标 | 度量方式 |
| --- | --- | --- | --- |
| 研究效率 | 单只股票完成「技术面 + 基本面」浏览 | 熟练用户 ≤ 3 分钟 | 可用性测试 |
| 数据覆盖 | A 股证券主数据与日线覆盖 | ≥ 99% 在市股票 | 数据质量报告 |
| 数据及时性 | 交易日日线可用时间 | 收盘后 2 小时内（以数据源可用为前提） | 任务完成时间 |
| 分析可信 | 回测与指标计算可复现 | 相同输入结果一致，抽样误差 ≤ 0.5% | 自动化测试 |
| 体验 | 本地环境首屏与常用接口 | LCP ≤ 2.5s，API P95 ≤ 500ms | 性能测试 |
| 稳定 | 每日数据任务成功率 | ≥ 99%，失败可重试并告警 | 任务监控 |
| 模拟交易 | 虚拟盘记账与撮合 | 与手工样例误差 ≤ 0.5% | 自动化测试 |
| 策略运行 | 定时生成信号并执行 | 成功率 ≥ 99%，失败可见可重试 | 任务监控 |
| 策略聚焦 | 单策略股票池与持仓上限 | ≤ 8 只，超限必须拒绝 | 校验测试 |
| Agent 决策 | 非法决策拦截率 | 非法/越权/池外决策 100% 拒绝 | 决策审计 |
| 可追溯 | 订单到决策链路 | 100% 可追溯 | 抽查审计 |
| 参考数据 | 指数/板块/每日基础指标/公司资料覆盖 | 与日线同步可用；公司资料 ≥95% | 质量报告 |
| API 契约 | OpenAPI + TypeScript client | 契约测试通过 | CI |
| 可解释性 | 决策轨迹覆盖率 | 100% 决策含上下文、信号、校验与结果 | 抽查审计 |
| 回放 | 回放一致率 | 规则策略 100%；LLM 以记录响应为准 | 回放测试 |
| 清理安全 | 账本数据误删 | 0 次 | 清理审计 |

> 说明：数据及时性受免费数据源限制，若无法满足，应在产品内明确展示「数据截至时间」，而不是降低指标口径。

## 2. 用户与使用场景

### 2.1 用户角色

| 角色 | 典型特征 | 核心诉求 | 优先级 |
| --- | --- | --- | --- |
| 个人投资者 | 有 1–5 年经验，关注 A 股 | 快速看盘、看财报、管理自选股 | P0 |
| 进阶交易者/量化爱好者 | 会写脚本，关注策略验证 | 小范围股票池、回测、绩效分析 | P1 |
| 策略作者 / Agent 配置者 | 会写 YAML/提示词，理解策略边界 | 配置策略与 Agent、评估模拟盘表现、审计决策 | P1 |
| 小型投研团队成员 | 2–10 人协作 | 共享自选/策略、权限隔离 | P1 |
| 系统管理员 | 部署与维护者 | 数据源配置、任务监控、备份恢复 | P0 |

### 2.2 核心工作流

```
发现  →  研究  →  验证  →  模拟  →  跟踪  →  复盘
 │        │        │        │        │        │
行情看板  个股详情   股票池/回测  虚拟盘执行  自选/预警  收益归因
板块排行  财务/技术   池内参数对比  多策略并行  组合跟踪  策略迭代
```

平台覆盖「研究、验证、模拟、跟踪、复盘」，**最终决策由用户负责**，产品不做买卖建议。策略可由不同 Agent 以 `advisory` / `auto` / `shadow` 模式执行；Agent 只产出结构化决策，平台负责校验、风控与虚拟下单。

| 账户 | 本地单用户 | 多用户与角色 | SSO |
| AI | — | — | 研究助手（RAG） |

### 3.2 明确不做（Out of Scope）

- 实盘下单、券商账户托管、资金划转。
- 桌面客户端（Electron/Tauri）、需要本地安装的行情终端。
- MVP 的远程/局域网访问与多用户认证（MVP 固定本地单用户）。
- 全市场条件选股、全市场扫描/排名、批量筛选全市场股票。
- Agent 直接访问互联网、执行任意代码、读写本地文件、调用券商接口。
- Agent 绕过平台校验直接下单。
- Agent 自主修改策略、风控参数或股票池上限。
- 通过删除 NAV、收益、成交或持仓数据来清理空间。
- 伪造回放、补全已过期缓存，或把可解释缓存当作绩效数据。
- 荐股、买卖点提示、收益承诺、代客理财。
- 高频/低延迟交易、Tick 级撮合。
- 社交、跟单、直播、资讯社区。
- 面向公众的 SaaS 多租户计费（本期不做，架构不排除）。

### 3.3 关键业务约束

以下约束是产品边界，任何页面、接口、导入入口都不得绕过：

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| C1 | 不做全市场扫描 | 不提供全市场条件选股、排名、批量扫描；不开放「扫描全部 A 股」类入口 |
| C2 | 一个虚拟账户挂多个策略 | 账户是资金容器，策略是独立运行单元，可同时存在多个 |
| C3 | 单策略最多 8 只股票 | 股票池 ≤8 只，最大持仓 ≤8 只；第 9 只必须被拒绝 |
| C4 | 策略只看自己的池 | 信号、回测、下单严格限定在策略股票池内，不得读取池外标的 |
| C5 | Agent 只能看策略池 | 上下文、工具结果、决策范围都限定在 ≤8 只池内 |
| C6 | Agent 不得直接下单 | 决策必须经 Schema 校验、业务校验、风控后才生成虚拟订单 |
| C7 | 决策必须结构化 | 模型语义输出匹配 `agent-response.schema.json`；运行时注入 envelope 后再匹配 `agent-decision.schema.json`；不合法即拒绝 |
| C8 | 默认人工审批 | 默认 `advisory`；`auto` 需显式开启并配置限额与 kill switch |
| C9 | Agent 隔离 | 不能读其他策略子账本；无网络、文件、Shell、券商工具 |
| C10 | 策略与 Agent 解耦 | 策略规范不声明 Agent；Agent 绑定、模式与回退在实例层配置 |
| C11 | 可解释数据与绩效数据分离 | 回放缓存是分析数据；NAV、收益、成交、持仓是账本数据，独立保存 |
| C12 | 缓存粒度 | 仅支持周/月/季/年四种粒度，默认 `quarterly`；一个策略同时只用一种 |
| C13 | 到期清理 | 超过配置保留期的可解释缓存可清理；清理不得删除账本数据 |
| C14 | 回放只读 | 回放不得下单、改持仓或调用 `order.place` |
| C15 | 过期不可伪造 | 缓存过期/损坏时返回 `CACHE_EXPIRED`，不得用部分数据拼凑回放 |

> 说明：8 只是**每个策略**的上限，不是每个虚拟账户的上限；同一账户下多个策略可以各自持有不同股票，但每个策略独立核算。

```
虚拟账户
 ├─ 未分配现金
 ├─ 策略 A 子账本（Agent A，股票池 ≤8 只，持仓 ≤8 只）
 ├─ 策略 B 子账本（Agent B，股票池 ≤8 只，持仓 ≤8 只）
 ├─ ...
 └─ 手动子账本（可选，独立核算）
```

### 4.1 FR-01 市场概览

**优先级**：P0 ｜ **版本**：MVP

**目标**：让用户在首页快速判断市场整体状态，决定是否继续研究。

**功能点**：

- 指数看板：上证指数、深证成指、创业板指、沪深 300、中证 500 等，支持配置显示项。
- 市场宽度：上涨/下跌/平盘家数、涨停/跌停家数（数据源可得时）、两市成交额。
- 板块排行：行业/概念板块涨跌幅、领涨股、成交额。
- 指数/板块详情：点击进入详情页，展示行情、成分/成员（可得时）与数据时间。
- 自选股快照与最近浏览。
- 全局数据时间戳，明确标识「最近交易日」。

**验收标准**：

- 非交易日打开首页，明确显示「最近交易日」，不得出现「今日」等误导性文案。
- 任一指数/板块卡片可点击进入对应详情；详情页展示成分/成员或明确的“数据不可用”；单个数据源失败时展示占位与原因，不白屏。
- 缓存命中时首页 LCP ≤ 2.5s。

**目标**：任意入口都能在 2 次操作内到达个股详情页。

**功能点**：

- 全局搜索：支持代码、名称、拼音首字母；输入防抖；键盘上下选择与回车跳转；最近搜索记录。
- 详情头部：最新价、涨跌幅、成交量/成交额、换手率、总市值/流通市值、52 周高低。
- 详情页签：概览、K 线、财务、公司资料；公司资料展示主营业务、行业、上市日期、实际控制人、网站/地区等字段，缺失显示“—”。
- 估值与市值：总市值、流通市值、PE(TTM)、PB 来自每日基础指标；公告与新闻为 P2。

**验收标准**：

- 无效代码返回友好的 404 页面，并提供搜索入口。
- 页签切换不触发整页刷新；详情页首屏 ≤ 2s（缓存命中）。

- 核心指标：PE(TTM)、PB、PS、股息率、ROE、毛利率、净利率、资产负债率、经营现金流/净利润。

- 行业对比：对股票池内（≤8 只）标的做指标横向对比；不提供全行业全量排名（P1）。

### 4.6 FR-06 股票池管理

**优先级**：P1 ｜ **版本**：V1

**目标**：让用户用最小的范围圈定要研究的股票，作为回测与虚拟盘策略的唯一标的来源；产品不提供全市场扫描。

**功能点**：

- 手工建池：按代码/名称搜索添加，或从自选股导入；支持 CSV 导入。
- 数量上限：**每个股票池最多 8 只**，第 9 只拒绝添加；导入超限时整批拒绝并提示具体行，不静默截断。
- 池内维护：排序、备注、标签、移除；展示基础行情与估值字段，但**只针对池内标的**，不做全市场排名或条件扫描。
- 复用：一个股票池可被多个策略/回测引用；策略运行时保存池快照，后续改池不影响历史结果。
- 与自选股的关系：自选股用于日常跟踪，可批量转为股票池；转入时执行 8 只校验。
- 改池规则：新增成员仍受 8 只限制；移除已有持仓的成员时，策略不得再对该标的加仓，并在策略页提示处理方式。
- 明确边界：页面不提供「扫描全市场」「全市场选股」「按条件筛选全部 A 股」入口。

**验收标准**：

- 添加第 9 只股票时被拒绝，提示上限为 8 只。
- 导入 9 行及以上时整批拒绝，错误信息能定位到超限行。
- 股票池只能展示/排序池内标的，无法通过该页面触发全市场查询。
- 策略引用的池以快照形式记录，改池后历史回测结果不变化。
- 同一股票池被多个策略引用时，修改需提示影响范围。
- 移除已有持仓的池成员后，策略无法再加仓该标的，并在策略页给出提示。

### 4.7 FR-07 策略回测

**优先级**：P1 ｜ **版本**：V1

**说明**：回测与虚拟盘共用同一套策略定义、撮合规则与绩效计算，区别仅在于「历史数据回放」与「未来行情推进」，避免两套引擎口径不一致。

**功能点**：

- 策略类型：规则型（定时调仓、条件触发）；自定义 Python 策略为 P2（沙箱执行）。
- 回测配置：起止日期、股票池（≤8 只）、初始资金、调仓频率、最大持仓数（≤8）、手续费、印花税、滑点、基准。
- 范围约束：策略只能对池内标的生成信号，池外标的不参与计算、不参与排序。
- 撮合规则：次日开盘/收盘成交可选；涨跌停、停牌不可成交；退市股票按规则处理。
- 输出：净值曲线、回撤曲线、年化收益、最大回撤、夏普、卡玛、波动率、胜率、盈亏比、换手率、交易明细、持仓快照。
- 可复现：记录数据版本、参数、股票池快照、代码版本。
- 异步执行：进度展示、取消、失败原因。

**验收标准**：

- 相同输入（数据版本、参数、股票池快照、代码）结果完全一致。
- 与手工计算的样例组合相比，收益/回撤误差 ≤ 0.5%。
- 能检测并提示「引用未来数据」的常见写法。
- 股票池超过 8 只或最大持仓配置超过 8 只时，拒绝提交并说明原因。
- 5 年日线、单策略回测 ≤ 30s。

### 4.8 FR-08 预警通知

**优先级**：P1 ｜ **版本**：V1

**功能点**：

- 规则类型：价格上穿/下穿、涨跌幅、成交量倍数、指标金叉/死叉、自选股相关事件（数据可得时）。
- 通知渠道：站内消息、邮件 SMTP、Webhook；企业微信/飞书/钉钉为 P2。
- 规则管理：启用/停用、冷却时间、静默时段、去重。
- 触发历史、通知失败重试。

**验收标准**：

- 模拟行情变化后 1 分钟内触发通知。
- 同一规则在冷却期内不重复通知。
- 渠道失败有记录、可重试，且不阻塞其他规则。

### 4.9 FR-09 组合跟踪

**优先级**：P1 ｜ **版本**：V1

**说明**：本模块只做「真实持仓」的手工记账，不提供撮合与下单；平台内的模拟交易统一放在 FR-13 虚拟盘，两者在 UI 与数据上明确区分。

**功能点**：

- 手工录入买入、卖出、分红、送转；支持 CSV 导入。
- 成本核算：加权平均成本，可选先进先出。
- 持仓视图：持仓市值、已实现/未实现盈亏、收益率。
- 组合净值、与基准对比、行业分布。
- 交易流水与复盘笔记。

**验收标准**：

- 加权成本与盈亏的样例计算正确。
- 分红送转后持仓数量与成本正确。
- 不接入券商、不涉及真实资金划转。

### 4.10 FR-10 数据管理

**优先级**：P0 ｜ **版本**：MVP

**功能点**：

- 数据源配置：类型、密钥、限频、启用/停用。
- 同步任务：证券列表、交易日历、日线、分钟线、财务、指数/板块、每日基础指标、公司资料；支持全量与增量、手动与定时。
- 数据管理页：数据源配置、任务触发、进度/日志、失败重试、质量报告、覆盖率与最后更新时间。
- 任务监控：状态、耗时、日志、失败重试、告警。
- 数据质量：覆盖率、缺失、重复、异常值、停牌标记；生成质量报告。
- 补数/重跑，任务幂等；记录数据版本。
- 初始化两阶段：应用与最近数据 30 分钟内可用；近 10 年历史数据异步回填并显示进度。

**验收标准**：

### 4.13 FR-13 虚拟盘交易

**优先级**：P1 ｜ **版本**：V1

**目标**：用模拟资金在接近真实的交易规则下验证交易想法；账户是资金容器，可挂多个策略，每个策略使用独立子账本、最多操作 8 只股票；账户、订单、持仓均与实盘隔离。

**功能点**：

- 虚拟账户：支持创建多个账户（名称、初始资金、基准、币种），可重置；账户总览展示总资产、未分配现金、策略占用资金、当日盈亏。
- 账户结构：**一个虚拟账户下可挂多个策略**；每个策略创建时分配初始资金，形成独立的策略子账本（现金、冻结资金、持仓、净值），账户保留未分配现金。
- 账户详情：按策略列出子账本的资金、净值、持仓数量（≤8）与运行状态，可下钻到策略明细。
- 手动下单：买入/卖出、市价/限价、数量；手动交易使用独立的「手动子账本」，不与策略子账本混算，也不计入策略绩效。
- 模拟撮合：按最新价或限价成交；手续费、印花税、过户费、滑点可配置；按市场规则处理 T+1、涨跌停、停牌。
- 日频模式下，收盘后生成的信号在 **下一交易日** 开盘/收盘撮合（可配置），禁止使用当日收盘后的信息回填当日成交；分钟级撮合为 P2。
- 订单生命周期：待成交、已成交、已撤销、已拒绝；部分成交为 P2；支持撤单并展示拒绝原因。
- 持仓与资金：按策略子账本隔离；**每个策略子账本最多持有 8 只股票**，第 9 只拒单；可用/冻结数量、成本价、市值、浮盈、已实现盈亏；每日收盘快照。
- 公司行为：分红、送转、配股（按数据可得性），支持手工调整并留痕。
- 模拟标识：账户、订单、持仓页面持续展示「模拟盘 / 虚拟资金」，避免与真实交易混淆。
- 审计：资金调整、重置账户、手工补录、策略资金分配均记录操作日志。

**验收标准**：

- 买入/卖出时的资金、持仓、交易单位校验准确；手续费计算与配置一致。
- T+1 冻结与解冻正确；涨跌停、停牌时拒绝成交并给出原因。
- 账户总资产 = 未分配现金 + Σ（各策略子账本现金 + 冻结资金 + 持仓市值）+ 手动子账本资产；与手工样例误差 ≤ 0.5%。
- 同一账户下 3 个策略可各自持仓与核算，资金、持仓互不串账。
- 单个策略尝试买入第 9 只股票时被拒绝，提示「单策略最多 8 只」。
- 重置账户需二次确认，重置后保留审计记录。
- 页面任何位置不出现「真实成交」「实盘」等误导性表述。

### 4.14 FR-14 策略配置与多策略运行

**优先级**：P1 ｜ **版本**：V1

**目标**：同一个虚拟账户下可配置多个策略，每个策略独立子账本、独立运行、最多操作 8 只股票；策略从「一次性回测」变成可持续运行的模拟实例。

**功能点**：

- 策略定义：名称、说明、**股票池（≤8 只）**、买入条件、卖出条件、仓位分配、最大持仓数（≤8）、调仓频率、风控规则（单票上限、止损、最大回撤停止）。
- 配置方式：可视化规则配置（P1）；自定义 Python 策略为 P2，需在沙箱中运行并限制资源。
- 策略实例：定义 + 参数组 + 绑定虚拟账户 + 分配资金 + 运行模式（手动运行 / 定时运行）+ 状态（草稿 / 运行中 / 已暂停 / 已停止）。
- 账户与策略：**一个虚拟账户可创建多个策略实例**；每个实例生成独立子账本，资金、持仓、任务隔离；账户层看到汇总，策略层看到明细。
- 生命周期：停止后不再产生新订单但保留持仓与记录；删除实例前必须先清仓或归档，避免持仓悬空。
- 范围约束：策略只能对股票池内标的生成信号；不扫描全市场、不做全市场排名；运行时保存股票池快照，第 9 只标的一律拒绝。
- 执行链路：数据更新 → 池内生成信号 → 风控校验 → 生成订单 → 虚拟盘撮合 → 记录持仓与日志；日频策略的信号基于当日收盘数据，订单在下一交易日撮合。
- 运行监控：实例净值、持仓、订单、信号、运行日志；支持暂停、恢复、停止、手动运行一次。
- 可追溯：每个信号与订单记录策略版本、参数、股票池快照、数据时间；暂停后不再产生新订单，恢复时不补发过期信号。
- 策略模板：提供均线交叉、动量、低估值等示例模板，仅作功能演示，不构成投资建议。

**验收标准**：

- 同一虚拟账户下可同时创建并运行至少 3 个策略实例，每个实例独立子账本，资金与持仓互不串账。
- 创建实例时分配资金不得超过账户未分配现金；分配或回收资金后，账户总资产不变。
- 每个策略的股票池与持仓均不得超过 8 只；添加第 9 只、配置最大持仓 9 只均被拒绝。
- 策略不会对股票池外的标的生成信号或订单；股票池快照可在运行记录中查看。
- 相同策略实例、相同数据、相同参数与股票池，生成的信号一致；信号只能基于已落库数据，订单时间不得早于信号时间。
- 单个实例异常（超时、数据缺失、下单失败）不影响同账户下其他实例，并产生告警。
- 每个订单可追溯到策略实例、信号、数据版本、参数与股票池快照。
- 暂停后不再产生新订单；恢复后不补发暂停期间的过期信号。
- 停止后保留持仓与历史记录；存在持仓时删除实例被拒绝，需先清仓或归档。
- 定时任务成功率 ≥ 99%，失败可在页面看到原因并重试。

### 4.15 FR-15 Agent 配置与执行

**优先级**：P1 ｜ **版本**：V1

**目标**：允许用户为同一虚拟账户下的不同策略配置不同 Agent；Agent 只输出结构化决策，平台负责上下文、校验、风控、虚拟下单与审计。

**功能点**：

- Agent Profile：创建、复制、版本化、暂停、归档；字段符合 `docs/specs/agent-profile.schema.json`。
- 类型：`rule`（确定性规则）、`llm`（模型决策）、`hybrid`（模型提议 + 规则否决/定量）；不同策略可绑定不同 Profile。
- 模型配置：provider、model、temperature、max tokens、seed、base_url；密钥只在服务端保存，禁止写入 Profile 文件。
- 提示词与约束：system prompt、目标、约束清单；提示词随 Profile 版本不可变。
- 工具与权限：工具白名单（行情、财务、指标、组合、下单建议）、只读/建议/自动权限；禁止网络、Shell、文件、券商工具。
- 风险与成本：最大持仓 ≤8、单票权重、单日换手、最大回撤、单笔金额、交易时段、每日调用/token/成本上限。
- 绑定：一个策略实例绑定一个 Agent Profile 版本；支持 `advisory`（人工审批）、`auto`（限额内自动虚拟下单）、`shadow`（只记录不成交）。
- 切换：运行中的实例禁止切换 Agent；需先暂停，切换后从下一交易日生效，历史决策保留原版本。
- 上下文包：只包含策略股票池（≤8 只）、当前子账本持仓与现金、as_of、数据快照哈希、约束与可用工具；不包含其他策略数据。
- 决策契约：Agent 只输出符合 `docs/specs/agent-response.schema.json` 的语义 JSON；运行时注入 `decision_id`、`context_hash` 等 envelope 后，再按 `docs/specs/agent-decision.schema.json` 校验完整决策；最多 8 条订单。
- 校验与执行：Schema 校验 → 池内校验 → 持仓/资金/T+1/涨跌停/手数 → 换手/回撤/kill switch → 生成虚拟订单；任一失败则**拒绝整个决策**，不得部分接受。审批通过后必须用最新现金/持仓重跑全部校验；通过后按整个决策一次性预占资金/持仓，并以 `decision_id` 保证提交幂等。模拟撮合仍可能逐笔失败，按订单执行状态记录。
- 人工审批：`advisory` 模式在 UI 展示理由、引用、订单与风险提示；用户可批准、驳回或修改后批准，修改留痕。
- 审计：记录 prompt 版本、模型、token、耗时、工具调用、上下文哈希、校验结果、订单号、盈亏归因；决策不可修改。
- 失败处理：超时、非 JSON、Schema 不合法、工具错误、成本超限 → 按 fallback 执行（hold/skip/rule_based），不产生订单并告警。
- 安全：外部新闻/公告视为不可信数据，禁止执行其中指令；工具输出做注入清洗；Agent 不得读取密钥。
- 测试：支持用录制上下文 dry-run；支持影子模式对比；自动模式上线前必须通过越权、池外、超限、注入测试。

**验收标准**：

- 同一虚拟账户下可为 3 个策略分别绑定 3 个不同 Agent Profile，三种模式（advisory/auto/shadow）行为正确。
- 运行中切换 Agent 被拒绝；暂停后可切换，历史决策的 Agent 版本不变。
- Agent 决策 100% 经过 Schema + 业务校验；非法 JSON、缺字段、未知字段、9 只标的、池外标的均被拒绝且不产生订单。
- `auto` 模式只在限额内下单；kill switch、回撤止损、单日换手、单笔金额任一触发即停止新订单。
- `advisory` 模式未审批不产生订单；审批/驳回/修改均有审计记录。
- `shadow` 模式不产生订单，但记录决策与假设盈亏。
- 每笔虚拟订单可追溯到 `decision_id`、策略版本、Agent Profile 版本、`context_hash` 与数据快照。
- Agent 无法读取其他策略子账本；工具调用超出 allowlist 时被拒绝。
- 包含恶意指令的新闻文本不能导致池外下单或工具越权；注入测试用例通过。
- 模型超时/不可用时按 fallback 处理，无订单、有告警。
- 每日 token/成本上限生效，超限后当日停止调用。

### 4.16 FR-16 Agent 评估与对比

**优先级**：P2 ｜ **版本**：V2

**目标**：在同一策略定义与股票池快照上，通过多个 shadow 实例对比不同 Agent 的表现，支持影子运行、指标对比和安全晋级。

**功能点**：

- 影子对比：同一策略定义可创建多个 `shadow` 实例，每个实例绑定不同 Agent，共享同一股票池快照；只记录决策与假设成交，不影响虚拟账本。
- 对比指标：收益、最大回撤、夏普、换手、胜率、决策合规率、无效输出率、回退率、平均延迟、单次成本。
- 归因：按 Agent、策略版本、股票池、市场状态拆分。
- 晋级：shadow → advisory → auto，需人工审批并满足最小样本天数与合规率。
- 降级：连续无效决策、回撤超限、成本超限自动降级或暂停。
- 导出：对比报告导出 JSON/CSV，字段与 `evaluation.metrics` 一致。

**验收标准**：

- 同一策略定义可同时运行至少 3 个 shadow 实例，分别绑定 3 个 Agent，互不影响虚拟账本。
- 对比页展示统一口径的指标与样本天数，缺失数据明确标注。
- 晋级/降级操作需审批并记录操作人、原因、版本。
- 报告可导出，字段与 Schema/指标定义一致。

### 4.17 FR-17 策略可解释性与回放

**优先级**：P1 ｜ **版本**：V1

**目标**：让每个策略的特征可量化、每次操作可解释、整个过程可按周期回放；回放数据与收益/交易数据严格分离。

**功能点**：

- 策略特征：`characteristics` 声明 `style`、`horizon`、`risk_level`、`typical_holding_days`、`expected_turnover_pct`、`market_regime`、`tags`；枚举与数值字段必须带单位或口径说明。
- 决策轨迹：每次决策保存上下文快照（仅池内 ≤8 只）、信号值、规则命中（或 Agent prompt/response）、工具调用、校验轨迹、持仓前后快照、订单关联。
- 可解释链：每个动作必须能还原「信号/规则 → 理由 → 校验 → 订单」，不允许无理由的买卖。
- 回放模式：`decision`（单次决策）与 `period`（某周期内全部决策）；展示时间线、输入、判断、校验、订单和持仓变化。
- 回放只读：不得下单、改持仓、调用 `order.place`；回放产生的假设结果单独标记。
- 回放确定性：规则策略必须完全可复现；LLM 策略默认回放**记录下来的响应**，重新调用模型属于单独的非确定性对比，必须显式标记。
- 范围隔离：只能回放本策略实例的缓存；跨策略访问返回 403。
- 失败处理：缓存过期、删除、损坏或 checksum 不一致时返回 `CACHE_EXPIRED` / `REPLAY_UNAVAILABLE`，不得用部分数据拼凑。
- 审计：每次回放记录操作人、模式、bundle、时间范围、结果哈希。

可量化特征口径：

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| `style` | enum | trend / momentum / mean_reversion / value / quality / event_driven / multi_factor / other |
| `horizon` | enum | intraday / daily / weekly / monthly / quarterly |
| `risk_level` | enum | low / medium / high |
| `typical_holding_days` | integer | 预期持仓交易日中位数，1–3650 |
| `expected_turnover_pct` | decimal | 年化换手率，0.30 = 30% |
| `market_regime` | enum array | trending / ranging / volatile / bull / bear / all |

**验收标准**：

- 100% 的决策具备上下文、信号、校验与结果轨迹；缺失时决策被标记为「不可解释」并告警。
- 规则策略相同输入回放结果完全一致；LLM 策略默认使用记录响应，回放结果一致。
- 回放过程中不产生订单、不改持仓；尝试写入被拒绝并记录安全事件。
- 缓存过期或损坏时返回明确错误与周期元数据，不生成伪造时间线。
- 跨策略回放被拒绝；回放日志完整可查。

### 4.18 FR-18 可解释缓存生命周期

**优先级**：P1 ｜ **版本**：V1

**目标**：按周/月/季/年管理可解释缓存，默认季度；按配置保留期清理过期数据，且绝不影响收益/交易数据。

**功能点**：

- 粒度：`weekly` / `monthly` / `quarterly` / `yearly`；默认 `quarterly`；一个策略同时只用一种粒度。
- 周期键：`2026-W43` / `2026-10` / `2026-Q4` / `2026`。
- 保留期：`retention_periods` 按所选粒度计数；默认 8 个季度；建议默认值为 12 周 / 24 月 / 8 季 / 5 年，全部可配置。
- 到期时间：`expires_at` = 周期结束时间 + 保留期。
- 缓存包：记录 `bundle_uri`、`checksum`、`size_bytes`、`decision_count`、`included_artifacts`、`status`（available/expired/deleting/deleted/corrupt）。
- 清理：定时任务 + 手动清理；手动清理必须先 dry-run 预览周期、数量、字节数。
- 保护：`pinned_periods` 不参与自动清理；清理只作用于可解释缓存，不触碰 NAV、收益、成交、持仓。
- 两阶段删除：`available → deleting → deleted`；保留 tombstone（周期、checksum、大小、删除时间）。
- 配额：展示缓存占用与到期预测；达到 80% / 100% 配额时告警。
- 权限：仅 owner/admin 可修改策略或执行清理；清理需二次确认并写审计。

**验收标准**：

- 新建策略时 UI 默认选择 `quarterly`；保存的规范必须显式写入粒度。
- 四种粒度生成的 `period_key`、`expires_at` 正确；跨年、跨季度边界计算正确。
- 到期清理只删除可解释缓存；清理前后 NAV、成交、持仓、收益数据完全一致。
- `pinned_periods` 在自动清理中不被删除。
- dry-run 统计与实际清理数量、字节数一致。
- 清理失败不会留下半删除状态；重试可继续。
- 清理操作可按策略实例、周期、操作人审计。

### 4.19 FR-19 参考数据与每日基础指标

**优先级**：P0 ｜ **版本**：MVP

**目标**：补齐市场概览与个股研究依赖的参考数据，避免实现时临时猜字段；所有数据只用于检索、详情和聚合展示，不用于全市场扫描。

**功能点**：

- 指数数据：指数目录、指数日行情（开高低收、成交量/额）、指数成分与权重、调入调出日期；支持指数详情页。
- 板块数据：行业板块目录与成员；概念板块在数据源可得时提供，不可得时明确标注“仅行业”；支持板块详情页。
- 每日基础指标：按证券与交易日保存总股本、流通股本、总市值、流通市值、PE(TTM)、PB、换手率；与日线同步更新。
- 公司资料：公司全称、主营业务、所属行业、上市日期、实际控制人、网站、地区、简介；记录来源与更新时间。
- 数据接入：通过适配器同步，支持全量/增量、幂等写入、失败重试与覆盖率报告；指数/板块/公司资料允许人工修正并留痕。
- 缺失处理：数据不可得时显示“—/暂无”，不得用 0 或推算值冒充；质量报告列出覆盖率。
- 边界：参考数据只服务于单标的检索、市场概览与聚合排行，不提供全市场条件筛选或批量扫描入口。

**验收标准**：

- 指数详情页可展示指数行情、成分/权重（可得时）与数据时间；板块详情页可展示成员与行情。
- 总市值、流通市值、PE(TTM)、PB 在日线更新后可用；抽样核对与数据源一致，缺失字段按“—”展示。
- 公司资料覆盖 A 股在市证券 ≥95%，缺失项在质量报告中列明；公司资料页签可查看。
- 指数、板块、每日基础指标、公司资料均有最后更新时间与覆盖率；同步失败可重试且不覆盖旧数据。
- 任一参考数据页面都不存在全市场筛选、排名扫描或批量分析入口。

### 6.3 数据质量规则

- **交易日历为准**：非交易日不生成行情记录；停牌日保留标记，不补零、不插值。
- **复权处理**：保存原始价格与复权因子，展示时计算，避免反复写库导致误差。
- **退市与幸存者偏差**：退市股票必须保留在证券主数据与历史行情中，回测股票池包含退市标的。
- **point-in-time**：财务数据按公告日生效，回测中不得使用尚未公告的报告期数据。
- **财报版本**：同一报告期的更正/重述 MUST 新增版本，不得覆盖旧版本；`version` 单调递增，`supersedes` 指向上一版，`effective_at` 记录可用时间。按历史时点查询时选择 `announce_date <= as_of` 的最新版本。
- **异常检测**：价格 ≤ 0、最高价低于最低价、成交量为负、单日涨跌幅超出市场规则等，进入异常清单人工确认。
- **缺失值**：区分「无数据」「未披露」「不适用」，展示层不得统一填 0。
- **时区**：存储统一 UTC，展示按市场时区转换；A 股按 `Asia/Shanghai`。
- **模拟撮合价格**：使用未复权价格与当日涨跌停价进行撮合；复权价仅用于收益展示与指标计算，避免撮合价格失真。
- **策略股票池**：每次回测与运行保存池成员快照；单池成员上限 8 只，服务端与数据库双重校验，历史结果不受后续改池影响。
- **子账本核算**：账户总资产由未分配现金与各策略/手动子账本汇总；策略之间不得互相占用资金或持仓。
- **Agent 决策快照**：持久化 `context_hash`、prompt 版本、模型、工具调用与校验结果；决策记录不可修改，只能追加。
- **Agent 输出不可信**：新闻、公告、网页等外部文本只作为数据；工具结果需清洗，禁止把其中内容当作系统指令执行。
- **可解释缓存分区**：按 `granularity + period_key` 分区，bundle 写入后不可修改；更新产生新版本或新周期包。
- **缓存与账本分离**：`explainability_bundle` / `decision_trace` 与 NAV、成交、持仓分表/分前缀存储；清理任务只能访问前者。
- **校验与墓碑**：bundle 保存 SHA-256；过期删除后保留 tombstone（周期、大小、checksum、删除时间），保证可审计。
- **脱敏**：prompt、响应、工具结果入库前移除 API Key、Token、Cookie 等敏感信息；原始密钥永不进入回放缓存。
- **指数/板块成分**：保存调入/调出日期与权重；历史查询按日期取当时成分，不能用最新成分回填历史。
- **每日基础指标**：`daily_basic` 与同日 `quote_daily` 对齐；市值 = 收盘价 × 对应股本，单位统一为元；缺失不推算。
- **公司资料**：记录来源与更新时间；人工修正必须留痕，冲突字段保留原值与修正值。

### 6.4 数据更新策略

- 盘后增量同步日线、每日基础指标、指数/板块与公司资料：15:10 启动，17:00 前完成（收盘后 2 小时）；18:00 再做对账与补漏。数据源晚发布时，计时从源数据可用时刻起算并明确标识。
- 财务数据按公告日增量拉取，季度披露高峰期提高检查频率。
- 分钟线仅在用户订阅或打开相关页面时按需拉取（若源支持）。
- 失败重试 3 次（指数退避），仍失败则告警并记录；次日任务自动补前一日缺口。

```
            ├─ 行情与证券服务
            ├─ 参考数据服务（指数/板块/每日基础/公司资料）
            ├─ 基本面研究服务
            ├─ 股票池、策略与回测服务
            ├─ 虚拟盘交易服务
            ├─ Agent 运行时（Profile / 调度 / 校验 / 工具网关）
            ├─ 回放与审计服务
            ├─ 预警与组合服务
            └─ 数据管理服务
                 └─ SQLite（单文件，唯一数据库）
                 ├─ Parquet + DuckDB（批量分析 / 回测）
                 └─ 数据源适配器 → AkShare / Tushare / yfinance / ...
```

### 7.3 参考技术栈

> 当前 MVP 实现使用 Rust/Axum/SQLite + Vite/React；下表同时标注生产目标与 MVP 替代项。

| 层 | 建议 | 备注 |
| --- | --- | --- |
| 前端 | Vite + React + TypeScript + Hallmark tokens/CSS | MVP 实现；生产可评估 Next.js |
| 图表 | TradingView Lightweight Charts / ECharts | K 线用专业图表库，统计图用 ECharts |
| 数据请求 | 原生 fetch + React state（MVP）/ TanStack Query（生产） | 缓存、重试、轮询 |
| 后端 | Rust + Axum + rusqlite | SQLite 直连，无 ORM/外部数据库 |
| 计算 | Rust 指标库（MVP）/ Polars / DuckDB（回测后续） | 指标、回测与虚拟盘计算 |
| 存储 | SQLite | 唯一数据库；无需 PostgreSQL/TimescaleDB |
| 缓存/队列 | 单进程调度 + SQLite snapshot | 不引入 Redis/Worker |
| 分析 | Parquet + DuckDB | 策略股票池的批量计算与回测 |
| Agent | LLM 网关 + 工具调用层 | 多 provider；密钥仅服务端保存；无网络工具 |
| 回放存储 | Parquet + 对象存储 + 元数据表 | 按周期分区、压缩、checksum、墓碑 |
| 部署 | 本机 cargo + Vite | 直接运行，不需要 Docker |
| 测试 | cargo test（MVP）/ Vitest + Playwright（后续） | 单测、组件、端到端 |

> 不引入 Electron/Tauri 等桌面壳；所有能力通过浏览器访问，部署在本地或服务器上。

### 7.4 部署形态

- **当前 MVP 开发环境**：`cargo run --manifest-path apps/api/Cargo.toml` + `npm run dev`（`apps/web`），SQLite 本地文件，默认只监听 `127.0.0.1`。
- **直接运行**：`cargo run` + `npm run dev`；不需要 Docker。
- **数据持久化**：SQLite 单文件 + 本地备份；不引入其他数据库。
- **团队/云端/局域网（V1）**：同一套镜像部署到云主机或 NAS，启用 HTTPS、登录与定期备份；MVP 不开放。
- **数据持久化**：数据库与数据文件挂载宿主机卷，容器可随时重建。

### 7.5 关键设计约束

1. 前端不直连数据源，所有外部数据经后端适配器。
2. 指标、回测与虚拟盘计算放在后端，保证多端一致与可复现。
3. 回测与虚拟盘共用策略定义、撮合规则与绩效口径，避免两套逻辑。
4. 所有回测与模拟交易结果绑定数据版本，数据更新后旧结果标注「数据已变更」。
5. 长任务一律异步化，接口只返回任务 ID。
6. 关键操作写审计日志（数据源配置、删除、回测提交、虚拟盘重置、策略启停）。
7. 策略计算入口只接受 ≤8 只的股票池（`pool_id`），不提供全市场扫描 API；任何批量任务都必须携带池标识。
8. Agent 输出必须经过 Schema 与业务校验；服务端不信任模型输出，校验失败一律 fail-closed。
9. Agent 工具白名单化：默认无网络、无文件、无 Shell、无券商接口；工具结果按不可信数据处理。
10. Prompt 版本与决策记录绑定，发布后不可修改；每次决策保留 `context_hash` 与工具调用哈希。
11. 回放只读：不得调用 `order.place`、不得写持仓；回放服务使用只读数据库连接。
12. 清理任务只能访问 `explainability_*` 表与对象前缀；禁止访问 NAV、成交、持仓表。
13. 读取 bundle 前校验 checksum 与 status；过期、删除、损坏一律返回明确错误，不拼凑回放。

## 8. 接口需求

### 8.1 通用约定

- 风格：REST，前缀 `/api/v1`，JSON 传输，OpenAPI 自动生成文档。
- 响应结构：`{ "code": 0, "message": "ok", "data": ..., "request_id": "..." }`。
- 分页：`page`、`page_size`，返回 `total`；默认 20，最大 200。
- 时间：ISO 8601，带时区；交易日使用 `YYYY-MM-DD`。
- 错误码：4xx 客户端错误，5xx 服务端错误；业务错误附 `code` 与可读信息。
- 鉴权：MVP 固定本地单用户、仅回环地址、可免登录；远程访问与 Session/JWT 属 V1。
- 契约：OpenAPI 覆盖全部接口，CI 生成 TypeScript client 并执行契约测试。
- 限流：按 IP + 用户维度，防止误用与滥用。

## 9. 合规、安全与免责

### 9.1 产品合规

- 页脚、个股详情、回测、虚拟盘与 AI 回答处展示免责声明：**「本平台仅用于个人学习与研究，所有数据与分析结果不构成投资建议，据此操作风险自担。」**
- 虚拟盘必须单独提示：**「模拟盘使用虚拟资金与模拟撮合，成交结果不代表真实市场，不构成投资建议。」** 账户、订单、持仓页面持续显示「模拟」标识。
- Agent 决策必须标注 **「AI 生成 / 模拟盘执行」**，展示 Agent 名称、版本、模型与决策时间；`auto` 模式提供显眼的 kill switch 和人工复核入口。
- 回放缓存可能包含 prompt、工具结果与决策理由，仅 owner/admin 可访问；导出前必须脱敏。
- 清理策略必须向用户明示：只删除可解释缓存，不删除收益、成交与持仓；删除后该周期不可回放。
- Agent 不提供投资建议、不承诺收益；所有 Agent 输出仅作为模拟盘研究记录。
- 不提供明确的买入/卖出指令，不承诺收益，不使用「必涨」「稳赚」等表述。
- 不代客理财、不接触用户资金、不接入券商交易接口。
- 若未来对外提供服务，需评估是否涉及证券投资咨询业务资质。

### 9.2 数据合规

- 遵守各数据源服务条款与 robots 协议，限频抓取。
- 标注数据来源与更新时间；不转售、不再分发原始数据。
- 商业使用前取得相应授权；实时行情需交易所或数据商授权。
- 新闻/研报仅做摘要与引用，注明出处，不整篇转载。

### 9.3 安全与隐私

- 默认仅监听本机；对外部署强制 HTTPS 与登录。
- 密钥通过环境变量或加密配置管理，禁止提交到代码仓库。
- 收集最少必要信息；用户数据支持导出与删除。
- 依赖定期扫描漏洞；生产环境关闭调试接口。
- 备份文件加密存储，恢复流程需验证。

## 10. 迭代计划

> 以下为 1–2 名全栈开发的粗略估算，实际以团队规模与数据源验证结果为准。

| 阶段 | 周期 | 范围 | 出口标准 |
| --- | --- | --- | --- |
| M0 需求与验证 | 1 周 | 本文档、页面原型、数据源可用性验证 | 关键数据源能稳定拉取样本数据 |
| M1 数据底座 | 2 周 | 数据模型、适配器、同步任务、参考数据、质量报告 | 证券/指数/板块/每日基础/财务可增量更新 |
| M2 行情与个股 | 2–3 周 | 首页、指数/板块详情、搜索、个股详情、自选、K 线与指标 | 核心浏览流程可用 |
| M3 基本面与打磨 | 2 周 | 公司资料、估值分位、数据管理页、设置页、API client、监控、部署与备份 | MVP 验收通过 |
| M4 股票池与回测 | 3 周 | 股票池（≤8 只）、回测引擎、绩效报告 | 池内结果可复现、误差达标 |
| M5 虚拟盘与策略运行 | 3 周 | 虚拟账户、模拟撮合、策略配置、同账户多策略并行（每策略 ≤8 只） | 同一账户下 3 个策略稳定并行 |
| M6 Agent 配置与执行 | 3 周 | Agent Profile、advisory/auto/shadow、校验与审计 | 3 个 Agent 同账户稳定运行 |
| M7 可解释性与回放 | 2 周 | 策略特征、决策轨迹、周期 bundle、只读回放、清理 | 季度缓存可按期回放 |
| M8 预警与组合 | 2 周 | 规则引擎、通知、真实持仓核算 | 触发与计算正确 |
| M9 AI 研究与多用户 | 按需 | RAG、权限、移动端 | 单独评审后启动 |

**里程碑原则**：

- M1 不通过，不进入 M2：数据不稳定，上层功能没有意义。
- M4 的撮合与绩效引擎必须先稳定，M5 虚拟盘直接复用，避免两套口径。
- M6 的 Agent 运行时必须建立在 M5 的虚拟盘与校验链路上；不允许 Agent 直接写订单表。
- M7 的回放数据必须与 M5 的子账本分离，清理任务不得触碰账本表。
- 每个阶段结束做一次演示与范围复盘，冻结下一阶段需求。
- MVP 总周期控制在 9–11 周（含参考数据与页面补齐）；V1（股票池、回测、虚拟盘与多策略、Agent 执行、可解释与回放、预警与组合）再增加 12–14 周，避免范围蔓延。

## 11. 验收标准

### 11.1 MVP 验收清单

- [ ] `docker compose up` 后 30 分钟内可访问首页并看到最近交易日数据；近 10 年历史在后台回填且进度可见。
- [ ] 纯 Web 访问：浏览器直接打开即可使用，不依赖桌面客户端或本地安装包。
- [ ] 不提供全市场条件选股/扫描入口；行情数据仅用于浏览、检索与聚合展示。
- [ ] 覆盖 A 股证券列表、指数/板块、每日基础指标、公司资料；历史日线最终覆盖 ≥99%。
- [ ] 首页、指数/板块详情、搜索、个股详情、公司资料、自选股、K 线指标、基本面概览可用。
- [ ] 数据管理页与设置页可用；数据任务支持增量、重试、断点续传、质量报告与手动补数。
- [ ] 核心指标（MA/MACD/KDJ/RSI/BOLL）有单元测试与固定样本校验。
- [ ] OpenAPI 覆盖 MVP 接口，TypeScript client 生成并通过契约测试。
- [ ] 关键页面展示数据来源、更新时间与免责声明；请求/任务指标与错误追踪可用。
- [ ] 备份与恢复脚本可用，恢复后数据一致。
- [ ] 无 P0/P1 缺陷，性能指标达到 NFR-01～NFR-04。

### 11.2 V1 验收补充（股票池、虚拟盘、策略与 Agent）

- [ ] 虚拟账户可创建、重置，模拟下单、撤单、持仓与资金核算正确。
- [ ] T+1、涨跌停、停牌、手续费与印花税规则按配置生效。
- [ ] 同一虚拟账户下至少 3 个策略可并行运行，每个策略子账本的资金与持仓互不串账。
- [ ] 每个策略股票池与持仓均 ≤8 只，第 9 只被拒绝；股票池页面无全市场扫描入口。
- [ ] 信号与订单可追溯到策略版本、参数、股票池快照与数据时间。
- [ ] 暂停、恢复、停止行为符合预期，单实例异常有告警且不影响同账户其他实例。
- [ ] 模拟盘标识与免责声明在账户、订单、持仓页面持续可见。
- [ ] 至少 3 个不同 Agent Profile 可绑定 3 个策略，并正确执行 advisory/auto/shadow。
- [ ] Agent 决策 100% 经 Schema + 业务校验；非法输出、池外标的、第 9 只均不产生订单。
- [ ] 每笔订单可追溯 `decision_id`、`context_hash`、Agent Profile 版本与数据快照。
- [ ] kill switch、回撤止损、单日换手、单笔金额、每日成本上限生效。
- [ ] Prompt 注入测试通过：外部文本不能诱导池外下单或工具越权。
- [ ] Agent 无法读取其他策略子账本，无法访问网络、文件、Shell 或券商接口。
- [ ] 每个策略声明完整、可量化的 `characteristics`（风格、周期、风险、持仓天数、换手、市场状态）。
- [ ] 100% 决策保存上下文、信号、规则/Agent、校验与持仓前后轨迹。
- [ ] 默认缓存粒度为季度；周/月/季/年四种粒度的周期键与到期时间计算正确。
- [ ] 回放只读，不产生订单、不改持仓；规则策略可复现，LLM 默认回放记录响应。
- [ ] 过期清理只删除可解释缓存，NAV、收益、成交、持仓数据完全不变；保留 tombstone。
- [ ] 过期/删除/损坏缓存返回 `CACHE_EXPIRED` / `REPLAY_UNAVAILABLE`，不伪造回放。

### 11.3 Definition of Done

一个需求完成需同时满足：

1. 功能通过验收标准，边界与异常场景已覆盖。
2. 单元测试/集成测试通过，核心计算覆盖率达标。
3. API 文档、指标口径文档、部署文档同步更新。
4. 通过代码评审与 CI（lint、test、build、依赖扫描）。
5. 无新增 P0/P1 缺陷，性能无明显回退。

## 模块职责修订（2026-10-25，以此为准）

量化中心是指标与策略的定义库，不绑定个股、股票池、账户或资金权重，不触发针对个股的运行。

| 对象 | 量化中心 | 实盘（模拟资金与成交） |
| --- | --- | --- |
| 指标 | 公式、单位、可用时间、缺失处理、解释边界 | 对选定股票计算指标值 |
| 策略模型 | 输入、学习方法、入场、退出、仓位算法、参数边界、验证要求与版本 | 选择模型版本，创建运行实例 |
| 股票 | 不关联 | 用户选定，每实例最多 8 只，禁止全市场扫描 |
| 权重 | 描述仓位算法，不配置账户资金 | 设置策略间资金权重；组合总配置不得超出可分配资金，剩余为现金 |
| 动态调优 | 定义允许优化的参数空间与选择准则 | 基于实例股票历史训练，保存参数、时间隔离验证和输入快照；不覆盖模型定义 |
| 运行结果 | 不展示个股信号或账户收益 | 保存信号、风险校验、模拟执行与归因 |

模型模板、实例训练参数、策略间资金权重、股票目标仓位是四个不同对象。自动调参不得自动改写资金权重或放宽风险限制。
现有 strategy.schema.json 含必填 universe，仍是旧版可执行策略契约；新页面定义库仅为说明，不冒充该契约。后续通过版本化模板契约和实例绑定迁移，禁止删除旧历史或跳过现有校验。

当前 UI：量化中心提供指标字典和 AK-State 研究草案；旧版固定池监控保留在实盘的独立入口。选股、权重保存、训练部署闭环尚未接入，不能据此声称模型已运行。

### 量化定义计算契约补充（2026-10-26）

量化中心保持不关联个股；策略详情必须列出数据字段、PIT连接、特征公式、训练标签/窗口/目标、专属门槛、资金权重整合和上下文流转。实现状态与目标算法分别标记，不把模型叙述当作执行DSL。具体见 [计算与上下文契约](research/quant-engine-calculation-contract.md)。研究方向使用可见分类按钮替代原生下拉，页面采用紧凑标题与工具栏。
