# Spec Delta

## Purpose

为 AlphaK MVP 提供可靠的 A 股数据底座：证券主数据、交易日历、日线与财务数据，以及可替换的数据源适配、增量同步、质量检查与补数能力。数据用于检索、个股详情和聚合行情展示，不用于全市场扫描。

## ADDED Requirements

### Requirement: A 股证券主数据

系统 MUST 维护 A 股证券主数据，至少包含代码、名称、交易所、板块、行业、上市日期、退市日期与在市状态；代码统一为 `6位数字.交易所` 格式。退市证券 MUST 保留，不得物理删除。

#### Scenario: 首次导入证券列表
- **WHEN** 管理员触发证券列表全量同步
- **THEN** 系统写入全部在市与退市 A 股证券，并为每条记录补齐交易所与行业字段

#### Scenario: 退市证券保留
- **WHEN** 某证券从数据源的最新列表中消失并标记为退市
- **THEN** 系统将其状态更新为退市且保留历史记录，搜索仍可按代码命中并显示退市标识

### Requirement: A 股交易日历

系统 MUST 维护交易日历，并以交易日历驱动行情同步、数据新鲜度判断与图表日期轴；非交易日 MUST NOT 生成行情记录，停牌日 MUST 保留停牌标记而不是补零。

#### Scenario: 非交易日同步
- **WHEN** 同步任务在周六运行
- **THEN** 系统不生成新的交易日行情，并将任务标记为“非交易日跳过”

#### Scenario: 停牌日展示
- **WHEN** 用户查看某股票停牌期间的 K 线
- **THEN** 系统显示停牌标记，成交量显示为 0 或空值，不使用插值价格

### Requirement: 日线行情

系统 MUST 存储日线开盘、最高、最低、收盘、成交量、成交额、换手率与复权因子，并以证券代码和交易日建立唯一约束；重复同步 MUST 幂等，不得产生重复行情。

#### Scenario: 重复同步幂等
- **WHEN** 同一交易日的日线任务被重复执行
- **THEN** 系统更新或忽略已有记录，数据库不出现同一证券同一日的重复行

#### Scenario: 复权展示
- **WHEN** 用户切换前复权、后复权或不复权
- **THEN** 系统基于原始价格与复权因子计算展示价格，不改写原始行情记录

### Requirement: 财务数据

系统 MUST 存储利润表、资产负债表、现金流量表与关键财务指标，并记录报告期、公告日期与不可变版本；查询与后续回测 MUST 只使用公告日期已到且当时可见的版本，避免未来数据。

#### Scenario: 公告日之前不可用
- **WHEN** 某季度报告尚未公告
- **THEN** 系统在个股财务页显示“未披露”，且不把该报告期数据用于任何计算

#### Scenario: 报告期切换
- **WHEN** 用户切换年度/季度或同比/环比
- **THEN** 系统展示对应报告期的数据，并在页面上标注报告期与公告日期

### Requirement: 财报版本与历史可复现

同一证券、报告期与报表类型的财务数据 MUST 以不可变版本保存；更正或重述 MUST 新增版本并用 `supersedes` 指向上一版，MUST NOT 覆盖旧版本。历史查询 MUST 选择查询时点已公告的最新版本。

#### Scenario: 初次公告
- **WHEN** 某公司首次公告 2026 年半年报
- **THEN** 系统保存 version=1，记录公告日与采集时间，并标记为当前版本

#### Scenario: 更正公告
- **WHEN** 该公司随后发布更正公告
- **THEN** 系统新增 version=2、supersedes=1，旧版本仍可按原公告日查询，当前版本指向 v2

#### Scenario: 历史时点查询
- **WHEN** 查询 2026-08-01 时点可用的财务数据
- **THEN** 系统返回当时已公告的版本，不返回之后才发布的更正版本

### Requirement: 数据集级多源主备

系统 MUST 通过统一适配器接入真实公开行情源，但按数据集分别配置主源与备源，MUST NOT 使用一条跨数据集的通用 fallback 链。首批 MUST 覆盖个股日线、行情快照与指数数据，至少接入东方财富与腾讯两个源；新浪用于交叉校验，巨潮用于财务/公告，通达信在后续批次评估。

#### Scenario: 主源失败切备源
- **WHEN** 个股日线主源超时或返回字段不完整
- **THEN** 系统只对个股日线数据集切换到备源，其他数据集的主备状态不受影响

#### Scenario: 小样本确定优先级
- **WHEN** 首批用 3 只股票、2 个指数和最近 5 个交易日比较两源
- **THEN** 系统记录日期、OHLC、成交量单位、收盘价容差与故障切换结果，再确定默认主备顺序

#### Scenario: 不使用通用备用链
- **WHEN** 指数主源失败但个股日线主源正常
- **THEN** 指数可切到自己的备源，个股日线不因指数失败而切源

### Requirement: 双源成功条件与事务发布

一次同步 MUST 仅当数据日期、覆盖范围、字段口径与质量校验均通过时才算成功；写入 MUST 在事务内完成，并记录 `source`、`batch_id`、`fetched_at`。任务 MUST 支持部分成功、缺口补齐、限时重试、来源冷却与后续自动重试；发布范围 MUST 严格限定本次请求的 symbol/date，MUST NOT 晋升旧批次或越界更新。

#### Scenario: 部分成功
- **WHEN** 3 只证券中 2 只从主源成功、1 只主源失败但备源成功
- **THEN** 任务标记为部分成功，记录每只证券的来源，并以事务写入成功记录

#### Scenario: 缺口补齐
- **WHEN** 请求区间内某交易日无数据
- **THEN** 系统将其列为缺口并重试；补齐后只发布该缺口，不覆盖区间外数据

#### Scenario: 质量失败不入库
- **WHEN** 某行最高价低于最低价或成交量非法
- **THEN** 该行不进入正式行情表，任务记录质量失败原因，已有数据保持不变

### Requirement: 过期状态与禁止 mock 回退

全部来源失败时，系统 MUST 保留最后成功数据并标记为过期，MUST 显示数据截至时间；MUST NOT 自动回退 mock、演示种子或伪造行情。过期数据可用于只读研究，但 MUST 在首页、个股页与数据管理页可见地提示，不得标成最新。

#### Scenario: 两源均失败
- **WHEN** 东财与腾讯在重试和冷却后均失败
- **THEN** 任务失败，最后成功数据仍可读，页面显示“数据已过期/截至某日”，不生成 mock 行情

#### Scenario: 恢复后清除过期
- **WHEN** 后续重试成功写入新批次
- **THEN** 数据集新鲜度恢复为 fresh，并显示新批次的来源与更新时间

### Requirement: 不复权行情与复权因子分离

系统 MUST 将不复权 OHLCV 与复权因子分开管理；复权因子 MUST 记录来源与批次。展示前复权/后复权时 MUST 由原始价格与因子计算，MUST NOT 改写原始行情。发布时 MUST 记录行情批次与复权批次，二者可独立重试与审计。

#### Scenario: 复权因子独立失败
- **WHEN** 原始日线成功但复权因子源失败
- **THEN** 原始行情仍可发布并标记“复权因子待补齐”，不把因子写成 1.0 冒充成功

#### Scenario: 批次审计
- **WHEN** 管理员查看某日行情
- **THEN** 系统可追溯该行的 `source`、`batch_id`、抓取时间与对应的复权因子批次

### Requirement: 增量同步任务

系统 MUST 支持证券列表、交易日历、日线与财务数据的全量与增量同步，支持手动与定时触发；任务 MUST 具备状态、日志、失败重试与断点续传，重复执行 MUST 幂等。

#### Scenario: 日线增量同步
- **WHEN** 交易日收盘后定时任务运行
- **THEN** 系统只补齐缺失交易日的数据，并在任务详情中显示新增、更新、跳过与失败数量

#### Scenario: 失败重试
- **WHEN** 同步任务因数据源超时失败
- **THEN** 系统按配置重试，仍失败时标记任务失败、保留已完成进度并发出告警

### Requirement: 数据质量报告

系统 MUST 为每个数据集生成质量报告，至少包含覆盖率、缺失数、重复数、异常数与最后更新时间；异常至少覆盖价格小于等于 0、最高价低于最低价、成交量为负与单日涨跌幅异常。

#### Scenario: 查看质量报告
- **WHEN** 管理员打开数据管理页
- **THEN** 系统按数据集展示覆盖率、缺失、重复、异常与最后更新时间

#### Scenario: 异常数据隔离
- **WHEN** 同步发现最高价低于最低价
- **THEN** 系统将该记录列入异常清单并阻止其进入图表计算，等待人工确认或重新拉取

### Requirement: 数据管理页

系统 MUST 提供数据管理页，展示各数据集（证券、日历、日线、财务、指数、板块、每日基础指标、公司资料）的覆盖率、最后更新时间、任务状态、失败原因与质量报告；MUST 支持手动触发、重试与补数。

#### Scenario: 查看数据状态
- **WHEN** 管理员打开数据管理页
- **THEN** 页面按数据集展示覆盖率、最后更新时间、最近任务状态与异常数

#### Scenario: 手动重试
- **WHEN** 管理员对失败任务点击重试
- **THEN** 系统创建新任务、保留原失败记录，并在页面显示进度与结果

### Requirement: 数据新鲜度与降级

交易日日线数据 MUST 在收盘后 2 小时内可用（以数据源可用为前提）；数据源故障时，系统 MUST 继续提供已缓存的历史数据，并在页面显示数据截至时间，不得白屏或把旧数据标成最新。

#### Scenario: 数据源故障
- **WHEN** 收盘后数据源持续不可用
- **THEN** 首页与个股页显示“数据截至上一交易日”，同步任务标记失败并告警

#### Scenario: 收盘后两小时 deadline
- **WHEN** 交易日 15:00 收盘且数据源正常发布
- **THEN** 日线同步在 17:00 前完成，页面显示本次更新时间；18:00 的对账任务只补漏，不作为首次可用时间

#### Scenario: 数据源晚发布
- **WHEN** 数据源在 17:00 后仍未发布当日日线
- **THEN** 系统将状态标记为“等待数据源”，从源可用时刻重新计时，并在页面显示数据截至时间

#### Scenario: 数据新鲜度展示
- **WHEN** 用户打开行情页
- **THEN** 页面显示最近交易日与数据更新时间，非交易日明确标注“最近交易日”

### Requirement: 数据源凭据安全

数据源密钥 MUST 只保存在服务端配置或环境变量中，MUST NOT 写入前端、日志、任务输出或版本库；界面只显示掩码。

#### Scenario: 查看数据源配置
- **WHEN** 管理员打开数据源设置
- **THEN** 系统显示密钥掩码与最后验证时间，不返回明文密钥

#### Scenario: 日志脱敏
- **WHEN** 同步任务记录请求日志
- **THEN** 日志中的密钥、Token 与 Cookie 被替换为掩码
