# Design

## Context

动机见proposal.md。实查main.rs/routes.rs/db.rs：已有行情、指标、workbench、数据持久化与来源适配，没有quant执行模块和订单账本。workbench规则符合度不是投资质量/市场机会分。已有研究依据为docs/research/strategy-decision-contract.md与strategy-auto-tuning.md；本文将它们转为实施边界，不重写研究权重。

现有input_manifest保存内容文件，data_reference提供保留引用；优先复用。quote_daily会更新，不能直接作为不可变实验输入。市场宽度接口的当前快照、历史序列、来源范围和时间精度不一致，不能把当前值补成过去情绪。当前123只页面样本与策略1–8只完全不同。

## Goals / Non-Goals

**Goals:** 首份真实固定池T0报告、同语义的模拟前向运行、54参数自动实验、可解释的无改善/失败结果；随后独立检验情绪T1。

**Non-Goals:** 高频/3秒交易、全市场扫描、真实委托、任意Python/LLM代码执行、首版完整Q/O、默认自动晋升。不把页面3秒行情刷新变成策略判断频率。

## Decisions

### 1. 一个Rust核心，两个时钟适配器

新增apps/api/src/quant/，首版保持现有Rust/Axum/SQLite部署，避免再运维Python服务。离线研究未来可导出数据给Python，但执行真相只有Rust版本。

| 模块 | 输入 → 输出 | 隔离职责 |
| --- | --- | --- |
| contracts | schema版本、规则配置 → 编译后类型 | schema+业务校验；拒未知版本 |
| dataset | 池、截止、数据能力 → manifest+质量报告 | 冻结来源、OHLCV单位、公司行动、日历与限制 |
| features | 截至当前的窗口 → 原始指标/有效性 | 纯计算；不得网络/写库 |
| strategy | 指标、前态 → 事件与目标建议 | 确定性状态机；无资金权限 |
| risk | 建议、净资产、持仓/在途 → 批准目标/拒绝 | 平台硬约束，Agent不可改 |
| execution | 目标、执行时证据 → 模拟订单/成交 | 原始价、费用、T+1、涨跌停、成交单位 |
| ledger | 订单/成交 → 现金、持仓、NAV | 唯一写入者，原子事务与幂等 |
| runner | 时钟、快照、状态 → 每步事件 | backtest与forward共用上述核心 |
| experiments | 冻结空间 → trials与选择报告 | 无权修改running实例或放宽风险 |

不用整段DataFrame一次算完交易：逐交易日推进，特征读窗口不能越过判断时点。经济结果不含随机运行ID/墙上时间；金额用整数分或固定精度十进制，数量整数，价格精度按证券规则；禁止浮点直接累计现金。

### 2. 每交易日的唯一顺序

开盘前处理已知公司行动和到期冻结 → 按当前可卖量、订单有效性及实际可观察执行价处理昨日订单 → 原子记成交/费用/资金/持仓 → 收盘可靠估值 → 计算截至收盘的指标 → 判断事件与退出优先级 → 多标的统一风险缩放/合法取整 → 校验并保存次日目标与状态。

回测next-open撮合只能由独立执行适配器读取下一交易日的原始开盘价；策略不能读该字段。前向定时任务如果错过开盘，不得事后读取日线open伪造成交，应等可信当时行情或标missed_execution；运行说明披露采样与延迟。首次版本采用下一交易日有效订单，未成交到期后由持久退出意图在后续日重新评估，不无限保留旧买单。

执行规则必须版本化，含证券/板块/生效日的交易单位、费用、涨跌幅、停牌状态、最小价格单位、T+1与零股卖出。没有足够盘口证据时，开盘位于涨跌停且成交能力不明按不可成交处理；日线有成交量不证明订单能排到。公司行动信息缺失的区间可研究但不能通过严格执行验证。

### 3. 先T0，再T1/T2，不静默降级

T0明确使用20/60均线、新趋势false→true、连续2次有效收盘跌破短均线退出、8%收盘止损；候选5交易日、退出冷却3交易日、加仓间隔5交易日。详细状态和冲突优先级继承B/S合同，T0明确删除Q/O、宽度与过热准入要求，以独立ID发布而非冒充完整多因子策略。

T0单票初建权重上限min(0.95/N,20%,0.5%/8%,流动性上限)，总仓位80%、计划组合止损风险3%、现金至少5%、日成交额30%、单笔5万元、组合回撤15%停机。以上均为既有研究候选参数，非验证结论。以实例净资产为分母；在途资金、费用和卖出未结算不得提前释放。多候选同比缩放，剩余不足合法买入单位留现金；参数不能盖过平台限额。

T1在相同T0版本上增加同口径宽度准入与拥挤限制；保存B、C原值、窗口、unknown及来源。先做单模块消融再做联合参数实验，防止收益差全部归因情绪。T2需要严格PIT财报/Q/O；T3文本后续增加，新闻事实与推断分开，外部文本无执行权限。

首轮真实池不默认拿全部123只或猜测8只；实验入口要求用户从样本显式选1–8只并冻结，界面可预填其选择但提交需验证。首次资金建议配置默认10万元，可编辑并写入实验。基准默认000300.SH，缺少一致口径基准时净收益仍可计算，超额为null且禁止按超额晋升。

### 4. 契约先升级，旧版本不重新解释

现有strategy.schema只有equal_weight/fixed_fraction/volatility_target，不能表达风险预算与状态机；Agent决策action是hold/buy/sell/rebalance，不能直接塞reduce。新增显式schema版本2.0.0及版本分发，保留1.0.0读取/校验；不强行迁移旧weight语义。旧版本暂不支持执行则返回UNSUPPORTED_EXECUTION_VERSION。

新增target-position契约，批准目标股数为执行真相，包含as_of、instance/version、manifest、symbol、current/target_quantity、stop_reference、约束清单、幂等键及原因。reduce在研究动作层存在，通过同版本适配器映射为卖出数量；不得给旧agent-decision添加未声明枚举。rule响应也过schema和业务校验，可信envelope由平台注入。策略仍不含Agent绑定。

现有shadow契约要求approval且不产生生产订单：增加明确的研究模拟路径，只写隔离研究账本，UI不提供其生产下单功能；不能借shadow绕过approval。自主模拟执行使用独立实例auto并显式开启；advisory只产建议。

表达式V1采用模板白名单与确定性状态机，不执行eval。允许字段/函数、null/unknown和窗口语义在新版本字典中冻结，旧表达式不自动升级。先实现T0所需最小集合，其余返回UNSUPPORTED_FUNCTION，不宣称整个DSL已实现。

### 5. 自动调优是实验，不是改写历史

首轮54组：短均线10/20/30、长60/90/120、退出确认1/2、止损6/8/10%。冻结仓位/成本/池，完整记录联动仓位影响。历史足够时按既有24月训练/6月验证滚动；不足则exploratory，可运行但不validated。各验证窗口以相同初始资金空仓独立起始，预热数据只建指标不交易；窗口末持仓按可信收盘价计入净值但不伪造成交，胜率只计窗口内闭合交易，窗口外收益不进入选择指标。研究收益标签跨界时按预注册最大标签窗口purge/embargo；持有期无上界时不能用任意固定天数声称已消除持仓重叠。

优化器只能取得开发分区manifest；冻结唯一候选哈希后，独立评估器才解锁最终测试分区。已查阅测试登记为used，不因换切分重置。排序沿用自动调优文档：有效/风险过滤 → 验证净超额日收益均值的跨窗中位数 → 最差回撤 → 换手 → 参数距离 → trial_id；现金及当前版同窗比较，无改善不换版。

成本翻倍、邻域敏感性、bootstrap作为独立子任务计入总预算；54是参数组数，不是所有验证任务数。单工作线程spawn_blocking运行，锁外加载冻结数据，短事务批量写；任务租约、心跳、取消、已完成trial内容键去重。重启检测过期租约，未提交trial重跑，已提交不重算。默认手动首跑，数据质量通过且存在新manifest才允许月度自动实验；此提案不创建系统定时任务。

### 6. 持久化设计：长期元数据/账本与有界分析缓存

以下均为**拟新增**表，不是当前数据库已存在。最终DDL、精确字段/索引/保留政策在实施前同步到既有持久化design.md，执行persistence-doc-update与harness；本提案不变更数据库指纹。

| 表/存储 | 主要内容 | 键/索引与约束 | 生命周期 |
| --- | --- | --- | --- |
| quant_strategy_version | 定义JSON、schema/code/hash、池版本、发布状态 | PK(strategy_id,version)，发布后不可改 | 长期，归档不物理删除 |
| quant_universe_version | 人工成员及选择/生效时点 | PK(hash)，成员唯一，业务强制1–8 | 长期 |
| quant_run | mode、manifest/版本、限制、父trial | PK(id)，unique内容运行键，(instance,as_of) | 长期 |
| quant_experiment | 分区、空间、评价/预算、已用测试、选择结果 | PK(id)，(status,created_at) | 长期 |
| quant_trial | 参数、状态、指标/覆盖、失败、run引用 | unique(experiment,param_hash,split,scenario) | 长期最小结果 |
| quant_job | 租约、心跳、取消、重试、进度 | PK(id)，(status,lease_until) | 运行中保留；终态90天，结果在experiment |
| quant_account | 模拟账户资金分配总账 | PK(id)，版本CAS | 长期账本 |
| quant_instance | 策略/Agent绑定、模式、分配/状态 | PK(id)，账户FK，运行版本不可热换 | 长期 |
| quant_state_checkpoint | 候选、冷却、锁、止损、最后事件/状态hash | unique(instance,sequence)，追加checkpoint | 长期最小状态 |
| quant_decision | envelope、目标、风控/拒绝、manifest引用 | unique(instance,as_of,symbol,rule_event) | 长期最小审计 |
| quant_order | 决策、目标差、冻结额、状态/剩余量 | unique(idempotency_key)，(instance,status) | 长期账本 |
| quant_fill | 执行证据、价量、费用、规则版本 | unique(execution_key)，订单FK | 长期账本 |
| quant_ledger_entry | 借贷/现金/证券变化、成交/公司行动引用 | unique(event_key,line_no)，(instance,sequence) | 长期追加，不缓存清理 |
| quant_position_lot | 买入日、可卖日、成本、剩余量 | (instance,symbol,available_date)，version CAS | 长期可重建投影，保留历史事件 |
| quant_nav | 现金/持仓估值/NAV、可信状态 | unique(instance或run,trade_date) | 长期业绩，缺价标uncertain |
| quant_analysis_bundle | 详细因子、解释、每日诊断文件引用 | PK(hash)，(period,expires_at) | 默认季度8季度，pin依赖/墓碑沿用策略 |
| 复用input_manifest/data_reference | 冻结OHLCV、宽度、日历、规则与代码清单 | hash与引用owner，禁止浮动current | 活跃实验/可重现证据pin；释放后按已有政策 |

历史实验使用独立run命名空间，与前向实例无资金混用。account分配操作和实例拨款同事务；总账户未分配+各实例净拨款守恒。ledger_entry为资金/股数权威，position_lot和NAV为可核对投影；交易写入事务含订单状态、fill、ledger与lot，失败全部回滚。资金与股票数量分别守恒，交易成本有对应费用分录。所有历史实验的decision、checkpoint、order、fill、lot和NAV同样必须带run账本作用域，唯一键包含该作用域；不能只用instance键让54组trial互相覆盖。

解释清理不删除最小decision/ledger。详细输入依赖过期后保留hash/版本/墓碑，复现状态变为snapshot_missing，不宣称永久复现。默认不永久pin所有54组的重复因子文件；共享输入按hash去重，运行期间引用保护，确认报告所需证据包可显式pin。

指标继承量化研究体系第8节，公式与配对规则固定：交易日净值收益、实际跨度年化、252交易日波动、显式无风险利率、峰值净值回撤、分批平仓FIFO闭合交易。未闭合交易只进入净值不进入胜率；零方差/无亏损等未定义比率为null，不用0填充。成本与公司行动分录必须能解释净值变化。

### 7. API与首版交付界面

拟新增/api/v1/quant：POST /experiments（池、区间、资金、模板、搜索/预算）；GET /experiments/{id}（进度/缺口）；POST /experiments/{id}/cancel；GET /experiments/{id}/trials；GET /runs/{id}/report、/nav、/trades、/decisions；POST /instances与运行/暂停动作。分页查询，CSV导出沿用一致过滤；写接口幂等键，参数不合法返回422，版本不支持显式错误。

先接已有量化/回测页面，展示真实任务、收益曲线、成交/拒单、参数比较、数据限制。无数据/未完成/失败不填模拟成功数字；研发报告、样本外和前向模拟分开。前端不承担风控。

## Risks / Trade-offs

- [免费数据历史时间/复权不完整] → 冻结数据能力矩阵；仅exploratory，T1缺历史不运行，不伪造情绪。
- [日线无法证明开盘排队成交] → 保守撮合，拒单原因与执行局限进入报告，前向用实际观察证据。
- [重复试验过拟合] → 试验族登记、测试只用一次、未见和前向确认，不以54组第一名当有效模型。
- [SQLite计算阻塞行情] → 锁外单计算线程、短事务、任务预算和取消；避免逐tick持久化。
- [schema与研究动作冲突] → 版本2适配及拒绝测试先行，不借metadata扩权。

## Migration Plan

1. 先发布新schema/有效与拒绝样例，更新契约索引；旧示例校验保持通过。
2. 按持久化设计更新表格、生命周期、指纹与迁移测试；备份后追加建表，不修改已有行情与样本。
3. 先本地fixture验成交和守恒，再显式选择1–8只真实样本跑T0并输出覆盖报告。
4. 发布只读报告，再启实验队列与有限搜索，最后显式启独立模拟实例和T1挑战者。
5. 回滚禁用quant调度/入口，不删除新账本；旧版本不认识新表可继续行情功能，恢复写入须新版本校验。

## 2026-10-25 首批可运行切片：策略管理与前向观察

本轮先交付 research-monitor-1，与 strategy.schema.json 交易策略严格区分：13 个冻结规则模板、每池1–8只、启停、手动批次、上海时区工作日交易时段每分钟检查已完成日线。未实现的回测、风控下单、撮合、账本和自动调优仍为后续任务，不能把条件满足当成买卖成交。日频在次日开盘观察上一完成日，不将盘中日线当成完整K线。

类型包括双均线20/60、10/30、20/60日放量突破、趋势回踩、20日动量、RSI修复、布林突破/修复、低波动趋势、放量、破位风险、池内情绪共振。情绪仅是策略池上涨占比代理，不冒充全市场情绪、舆情或资金流。所有阈值待验证。均线算术平均，RSI为最近14次涨跌幅金额的简单和（非 Wilder 平滑），波动为20次简单收益总体标准差，布林使用此前20收盘总体标准差。

quant_monitor 长期保存不可变研究定义（只允许启停）；quant_observation 长期保存输入包和输出，唯一键防止相同数据重写。信号三态：triggered=前日不满足而当日满足；condition_met=持续满足/情绪共振仅状态；watching=未满足；blocked=不足、过期、不齐。首轮以当下已知历史重建，非历史实时触发。暂停不删历史。采用未复权价格，除权可能伪触发；不宣称策略已验证。

明日 2026-10-26 开盘执行依赖进程、电脑、数据采集可用。调度仅研究，工作日不等于法定开市；缺失官方日历必须可见。收盘15:10后允许当日完整日线；源更新晚于15:15时，下一交易时段才获取该日新版本，可手动运行补查。

## 模块职责修订（2026-10-25，以此为准）

量化中心是指标与策略的定义库，不绑定个股、股票池、账户或资金权重，不触发针对个股的运行。

| 对象 | 量化中心 | 实盘（模拟资金与成交） |
| --- | --- | --- |
| 指标 | 公式、单位、可用时间、缺失处理、解释边界 | 对选定股票计算指标值 |
| 策略模型 | 输入、学习方法、入场、退出、仓位算法、参数边界、验证要求与版本 | 选择模型版本，创建运行实例 |
| 股票 | 不关联 | 用户选定，每实例最多 8 只，禁止全市场扫描 |
| 权重 | 描述仓位算法，不配置账户资金 | 设置策略间资金权重；组合总配置不得超出可分配资金，剩余为现金 |
| 动态调优 | 定义允许优化的参数空间与选择准则 | 基于实例股票历史训练，保存参数、时间隔离验证和输入快照；不覆盖模型定义 |
| 运行结果 | 不展示个股信号或账户收益 | 保存信号、风险校验、模拟执行与归因 |

模型模板、实例训练参数、策略间资金权重、股票目标仓位是四个不同对象。自动调参不得自动改写资金权重或放宽风险限制。
