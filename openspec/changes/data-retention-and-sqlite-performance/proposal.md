# Proposal

## Why

AlphaK 已有日线历史、实时快照、混合用途缓存和用户配置，但尚无统一保留与清理政策；3 秒刷新使逐行提交、整段 JSON 重写及共享连接锁的成本更明显。需要区分可丢弃的显示缓存与不可自动删除的研究证据、用户资产和模拟账本，支持可复现研究并控制 SQLite 增长。

## What Changes

- 建立覆盖现有表、浏览器状态、文件及未来策略数据的生命周期清单，明确当前事实、目标政策、时间单位、清理与备份边界；全部表格直接列于 `design.md` 的“入库数据、保存期限与清理规则”，无需跳转附件。
- 默认长期保留日线、财报版本、估值、参考资料历史、用户配置、审计和未来策略/实验/模拟账本。缓存按类型短期保留，运行状态与任务历史分别治理。
- 将大盘宽度等情绪研究证据从可覆盖的显示缓存中分离，输入经实验引用后冻结，禁止缓存清理破坏复现。
- 定义幂等、限量、可预览的缓存清理与备份轮换；默认季度可解释缓存到期清理必须保留墓碑，不能触碰账本。
- 实时报价每批至多 20 只，一批一个短事务，校验和网络请求在锁外；配置有限锁等待，保留已有 WAL 并增加监控、检查点及容量基准。
- 秒级数据按时间键增量 upsert，替代每次重写 360 根 JSON；默认不采集全量 3 秒历史，按需交易时段采样、去重与有限保留。
- 为后续独立读连接设性能触发门槛，回测加载冻结输入后在锁外计算。单次请求批量上限不等于策略池上限；策略仍最多 8 只。

## Capabilities

### New Capabilities

- `data-lifecycle`: 数据分类、引用保护、缓存清理、备份及恢复的一致性规则。
- `sqlite-workload-management`: 批量事务、锁等待、WAL、增量高频缓存和性能验收。

### Modified Capabilities

无。`openspec/specs/` 当前无已发布 capability；已有 `alphak-platform-mvp` 变更中的 market-data/platform-foundation 草案须在实施时保持兼容，不在本提案改写。

## Impact

涉及 `apps/api/src/db.rs`、`routes.rs`、`sources/store.rs`、`live.rs`、`market.rs`、`market_breadth.rs`、`workbench.rs`、`sync.rs`、备份脚本、数据管理接口及其前端。可能新增保留政策、清理审计、研究快照和短期 bar 表；不引入 Redis/PostgreSQL，不建立全市场扫描，不连接真实交易。本次只生成规划文档，不执行迁移、清理或数据库配置修改。
